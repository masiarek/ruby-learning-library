# A variable is a reference, not a box

**Level:** 101 · anyone who has been surprised that changing `b` changed `a`

**One line:** Assignment copies a reference, never the object, so after `b = a` a mutating method such as `<<` on `b` is seen through `a`, while `b = b + x` and `b += x` bind `b` to a new object and leave `a` alone — Python has the same model with one exception: `+=` on a list mutates it in place.

A Ruby variable holds a reference to an object; the object lives elsewhere and can have any number of names at once. There are two different things you can do with a name, and everything on this page follows from telling them apart. You can *mutate the object* — `<<`, `push`, `upcase!`, `[]=` — and every name that refers to it sees the change. Or you can *rebind the name* — `=`, and `+=`, which in Ruby is never anything but `b = b + x` — and no other name notices. A method's parameter is a name too, so a method can change the caller's object but cannot change what the caller's variable refers to. When you want an object of your own, `dup` makes a new one, one level deep.

## Reading the output

- **Row 1.** After `b = a` there is one array with two names. `<<` through `b` is seen through `a`, and `equal?` confirms they are one object.
- **Row 2.** `+` builds a new array and `=` binds `b` to it; `a` still refers to the old one, and `equal?` is now `false`.
- **Row 3.** `+=` is `b = b + [4]`, a rebinding, so `a` is untouched. Ruby has no in-place `+=`.
- **Row 4.** The same two operations on a string: `<<` changes the shared object (`s` sees `"xy"`), `+=` rebinds `t` to a new string (`s` stays `"xy"`, `t` becomes `"xyz"`).
- **Row 5.** `push_four` mutates the caller's array; `reassign` rebinds only its own parameter, so `orig` is unchanged and the new array comes back only as the return value; `upcase!` changes the caller's string in place.
- **Row 6.** `dup` copies one level: `c` is independent of `base`, but the inner array of `nested.dup` is still the same object as `nested[0]`. A `Marshal` round trip is the stdlib deep copy.
- **Row 7.** `Array.new(3, "x")` is one string three times over; the block form `Array.new(3) { "x" }` evaluates the block once per slot.

## Compared with Python

Python has the same model — its FAQ calls it *call by object reference* *(Not machine-checked here.)* — and rows 1, 2, 5, 6 and 7 print the same answers: assignment shares, `+` and `=` make a new list and rebind, a function sees the caller's list but cannot rebind the caller's name, `copy.copy` is shallow and `copy.deepcopy` is deep, and `[[]] * 3` is the same trap as `Array.new(3, "x")`. Row 3 is the difference: `b += [4]` on a list calls `list.__iadd__`, which extends the list in place and returns the same object, so `a` changes too and `a is b` stays `True`; in Ruby `+=` is a rebinding on every type. Row 4 is a difference of the opposite kind: a `str` is immutable, so there is no `<<`, `t[0] = "y"` is a `TypeError`, and `+=` can only rebind — which is why "strings are safe to share" is true in Python by construction and true in Ruby only for [frozen strings](../freeze_and_frozen_error/README.md).
