# A symbol is a name, not a string

**Level:** 101 · a Python programmer who has just met `:foo` and `{key: value}`

**One line:** A Ruby symbol is an immutable name of which exactly one object exists per spelling — `:a.equal?(:a)` is `true` while two `"a"` literals are two objects — and it is what Ruby uses for method names, hash keys and `&:upcase`; Python has one string type and covers the same ground with interning, `getattr` and `enum.Enum`.

A symbol is the thing you type after a colon: `:name`, `:upcase`, `:+`. It is not a string. There is exactly one `:a` in the whole program — every occurrence of the literal, and every `"a".to_sym`, evaluates to the very same object — and it is frozen, so it can never change. That is what makes it the right thing to be a *name*: Ruby names its methods with symbols — `methods` returns them, `send` takes one, `def` returns one — and a hash keyed by symbols is the ordinary way to pass options. A string is a sequence of bytes that you compare by content and may change in place; a symbol is an identity that you compare by identity. The program prints six numbered groups, and the Python twin prints the closest thing Python has for each.

## Reading the output

- **Row 1.** `:a.equal?(:a)` is `true`: two spellings of the same symbol are one object, whatever built them — a literal, `to_sym` on a literal, or `to_sym` on a string assembled at run time. Two `"a"` literals are two different `String` objects.
- **Row 2.** `:a == "a"` is `false`. They are different classes, `Symbol` and `String`, and `uniq` keeps both. `to_s` and `to_sym` cross over.
- **Row 3.** Every symbol is frozen. `Symbol#name` returns one shared frozen `String`, so appending to it is a `FrozenError`; `Symbol#to_s` hands back a fresh, unfrozen copy each time.
- **Row 4.** `%i[a b]` builds an array of symbols; a symbol with a space needs quotes, `:"hello world"`. `{a: 1}` is the symbol-keyed hash — `inspect` prints it back as `{a: 1}` and a string-keyed one as `{"a" => 1}` — and because `:k` and `"k"` are different objects, one hash holds both as two separate keys, and `{a: 1}["a"]` is `nil`. That trap has its own page: [string and symbol keys](../../16_Idioms_and_Gotchas/string_and_symbol_keys/README.md).
- **Row 5.** A method's name is a symbol: `send(:upcase)` calls it, `def greet; end` evaluates to `:greet`, `method(:upcase).name` is `:upcase`, and `methods` returns an array of them.
- **Row 6.** `Symbol#to_proc` turns `:upcase` into a block that calls that method on its argument, which is why `map(&:upcase)` and `inject(:+)` read the way they do. The [symbol to proc](../../03_Blocks_Procs_and_Lambdas/symbol_to_proc/README.md) page follows that `&`.

## Compared with Python

Python has no symbol type, so `str` does double duty as the text type and the name type: `getattr(obj, "upper")` takes a string, `dir()` returns strings, a function's `__name__` is a string, and a dict's keys are usually strings (rows 4 and 5). Two mechanisms cover the rest of a symbol's job. *Interning* gives "one object per spelling": `sys.intern` returns the canonical object for a string, and CPython interns identifier-like literals on its own, which is why `a = "abc"; b = "abc"; a is b` is `True` while a string built with `join` is a separate object until it is interned (row 1). *Enumerations* give a fixed set of named, immutable, identity-compared values: `Color.RED is Color.RED`, `Color["RED"]` looks a member up by name, `Color.RED == "RED"` is `False`, and a member cannot be reassigned (rows 2 and 3). Every `str` is immutable, so the frozenness Ruby reserves for symbols is simply how strings are (row 3). `dict(a=1)` is the nearest thing to the `{a: 1}` spelling, and its keys are still strings; row 4's ending runs the other way round from Ruby — `d["k"] = 1; d["k"] = 2` leaves one key, because there is only one kind of `"k"`. For `&:sym`, `operator.methodcaller("upper")` and `map(str.upper, …)` are the spellings (row 6).

# Kata: tally words under symbol keys, then move the same hash between symbol
# keys and string keys and watch what == thinks of the two.

words = %w[apple Banana cherry apple]
tally = words.map { |w| w.downcase.to_sym }.tally
puts "   symbol keys   #{tally.inspect}"
puts "   key classes   #{tally.keys.map(&:class).uniq.inspect}"

strings = tally.transform_keys(&:to_s)
puts "   string keys   #{strings.inspect}"
puts "   key classes   #{strings.keys.map(&:class).uniq.inspect}"

back = strings.transform_keys(&:to_sym)
puts "   strings == tally   #{strings == tally}"
puts "   back == tally      #{back == tally}"
puts "   tally[:apple]      #{tally[:apple].inspect}"
puts "   tally[\"apple\"]     #{tally["apple"].inspect}"
