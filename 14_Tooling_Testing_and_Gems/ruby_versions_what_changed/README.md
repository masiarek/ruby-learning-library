# What changed, 1.9 to 4.0

**Level:** 201 · anyone reading Ruby code or answers written for an older Ruby, and anyone who wants the Python timeline beside it

**One line:** Ruby's releases each added a few things you will meet in old code and new — keyword arguments (2.0), refinements (2.1), `&.` (2.3), pattern matching (2.7), keyword separation and Ractor (3.0), `Data` (3.2), `it` (3.4), a core `Set` (4.0) — and the program below asks this interpreter which of them it has, so the history is checked against the Ruby that ran it.

The table is prose *(Not machine-checked here.)*; every row of the program is a measurement. A feature is checked either by compiling a snippet (`RubyVM::InstructionSequence.compile` raises `SyntaxError` for syntax the parser does not know) or by asking a class whether a method or constant exists.

| Release | Year | What arrived |
|---|---|---|
| 1.9 | 2007 | YARV bytecode VM, strings carry an encoding, `{a: 1}` symbol-key syntax, `Enumerator`, `Fiber` |
| 2.0 | 2013 | keyword arguments, `Module#prepend`, refinements as experimental, `%i[]` |
| 2.1 | 2013 | refinements official, `def` returns a Symbol, `Rational`/`Complex` literals (`3r`, `2i`) |
| 2.3 | 2015 | `&.` safe navigation, `# frozen_string_literal: true`, `Hash#dig`, `Array#dig` |
| 2.4 | 2016 | `Fixnum` and `Bignum` merged into `Integer`, `Comparable#clamp`, `Regexp#match?` |
| 2.5 | 2017 | `rescue`/`else`/`ensure` inside `do…end` blocks, `yield_self`, `Hash#slice` |
| 2.6 | 2018 | endless range `(1..)`, `then`, `Proc#>>` and `<<`, `Array#union`, the first MJIT |
| 2.7 | 2019 | pattern matching (`case`/`in`) experimental, `...` argument forwarding, numbered block parameters `_1`, beginless range |
| 3.0 | 2020 | keyword arguments separated from positional (a `Hash` no longer fills `**opts`), Ractor, endless `def f = 1`, RBS and TypeProf, `Hash#except` |
| 3.1 | 2021 | `{x:}` hash shorthand, `Class#subclasses`, YJIT (experimental), pin expressions `^(expr)` |
| 3.2 | 2022 | `Data.define`, anonymous `*`/`**`/`&` forwarding, `Regexp.linear_time?` and the regex match cache, `Integer#ceildiv`, WebAssembly support |
| 3.3 | 2023 | Prism parser shipped as a gem, RJIT replaces MJIT, `Range#reverse_each`, `bigdecimal`/`csv`/`racc` warned as leaving the default gems |
| 3.4 | 2024 | `it` block parameter, chilled string literals (a warning on mutation, not an error), error messages quote names as `'name'` instead of `` `name' ``, Prism as the default parser, `**nil` in hash patterns |
| 4.0 | 2025 | `Set` in core (C implementation), `Ractor::Port` replacing `Ractor.yield`/`take`, ZJIT (a second JIT), `Ruby::Box` namespaces (experimental), `Warning.categories`, old `it`-shadowing warnings gone |

## Reading the output

Row 1 fixes the interpreter: a 4.x. Rows 2–12 are the features old tutorials assume you do or do not have, each answered `true` by this Ruby: keyword arguments and `prepend` (2.0), the `Refinement` class (2.1), `&.` and `dig` (2.3), one `Integer` class — `Fixnum` is no longer defined and `2**100` is an `Integer` like `1` (2.4), `rescue` inside a `do…end` block (2.5), `(1..)`, `then` and `>>` (2.6), `case`/`in`, `...` and `_1` (2.7). Row 9 is the 3.0 change that broke the most code: a hash passed positionally no longer fills `**opts`, so `kw.call({a: 1})` raises `ArgumentError` — the row prints `true` because it did. Rows 10 and 11 are the 3.1 shorthand and 3.2's `Data`, anonymous forwarding and `Regexp.linear_time?`. Row 12 requires `prism`, the parser that became the default in 3.4. Row 13 is 3.4: `it` compiles, `"a".frozen?` is `false` because a chilled literal is not frozen — it only warns on mutation when deprecation warnings are on — and the `NoMethodError` message quotes the name as `'foo'` in the new style. Row 14 is 4.0: `Set#add` has no Ruby `source_location` because `Set` is now C code in core, and the constants `Ractor::Port`, `RubyVM::ZJIT` and `Ruby::Box` exist. Row 15 prints the warning categories 4.0 knows, `:strict_unused_block` being the newest.

## Compared with Python

Python's timeline runs on a yearly cadence since 3.9 and the twin checks it the same way, with `compile()` for syntax and `hasattr` for library additions: the walrus operator and positional-only parameters (3.8), `dict | dict` and `str.removeprefix` (3.9), `match` statements, `zip(strict=True)` and `itertools.pairwise` (3.10), exception groups with `except*`, `tomllib` and `typing.Self` (3.11), and 3.12's nested quotes inside f-strings, the `type` statement, `def f[T]` generic syntax, `itertools.batched` and `sys.monitoring`. Rows 8 and 9 are where this library's two CI machines part ways: `copy.replace`, the free-threaded build and the new REPL arrived in 3.13, and template strings (`t"…"`) and deferred evaluation of annotations in 3.14, so those rows name the check but do not print its answer — the key must be identical under 3.12 on Ubuntu and 3.14 on macOS, and `hasattr(copy, "replace")` is `False` on one and `True` on the other. That is row 10's lesson: a feature probe is worth exactly the set of interpreters it ran on. Two contrasts with Ruby: Python's 2-to-3 break happened once, in 2008, and Ruby has never made a comparable one — 3.0's keyword separation is the largest — and Python removes things on a schedule (`distutils` in 3.12, `asynchat`/`imp` in 3.12 and 3.13's "dead batteries") where Ruby moves libraries out of the default set into bundled gems instead *(Not machine-checked here.)*.

```ruby
# Kata: a feature probe. `feature?` compiles a snippet and says whether this
# Ruby accepts it -- including a snippet from a Ruby that does not exist.
def feature?(name, src)
  RubyVM::InstructionSequence.compile(src)
  puts format("%-28s accepted", name)
rescue SyntaxError
  puts format("%-28s rejected (SyntaxError)", name)
end

feature? "2.3 safe navigation",      "a&.b"
feature? "2.7 pattern matching",     "case 1\nin Integer then :int\nend"
feature? "3.1 hash shorthand",       "x = 1\n{x:}"
feature? "3.4 it parameter",         "[1].map { it }"
feature? "imaginary: pipe operator", "1 |> puts"
feature? "imaginary: def without end", "def f(x) x * 2"
```
