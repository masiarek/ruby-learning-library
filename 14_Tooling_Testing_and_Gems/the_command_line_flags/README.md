# The command line is part of the language

**Level:** 201 · anyone who has typed `ruby file.rb` and wants to know what the other letters do — and which Python letters mean something else

**One line:** `ruby` takes flags for running code (`-e`), checking it (`-c`), warning about it (`-w`, `-W:category`), loading before it (`-r`, `-I`), turning a script into a filter (`-n`, `-p`, `-a`, `-l`), fixing the encoding (`-E`), switching engines and gems (`--yjit`, `--disable-gems`, `--enable=frozen-string-literal`) and dumping what the compiler made (`--dump=insns`); `python3` has a counterpart for most, and `-I`, `-s` and `-S` mean different things in the two.

Every row below starts a child interpreter — `RbConfig.ruby` is the Ruby running the page, `sys.executable` its Python — with the flags shown, feeds it stdin when the flag reads input, and prints the child's stdout, stderr and exit status. A temporary folder holds three tiny files: `ok.rb`, `bad.rb` (a `def` with no `end`) and `unused.rb` (an assigned-but-unused local), and a `lib/` folder with `helper2.rb`; their paths print as `DIR`. Read a row as a terminal session: the command, what came back.

## Reading the output

Row 1, `-e`, runs a string; several `-e` flags concatenate into one program. Row 2, `-c`, checks syntax only: `Syntax OK` for the good file, and for the bad one exit status 1 with Prism's message on stderr — the first line says `syntax errors found`, the rest (dropped here) draws the offending line with a caret. Row 3, `-w`, turns on the warnings that are off by default; `assigned but unused variable - x` is the one most people meet first. Row 4 shows the finer switches: `-W:deprecated` and `-W:no-deprecated` flip one category, while `-W0` sets `$VERBOSE` to `nil` (silence) and `-w` sets it to `true`. Row 5, `-r json`, requires a library before the program starts, and row 6, `-I DIR/lib`, prepends a folder to `$LOAD_PATH` so a bare `require "helper2"` finds it — the two flags a test runner uses as `-Ilib -Itest`. Row 7 is the Perl heritage: `-n` wraps the program in `while gets … end` with each line in `$_`; `-p` does the same and prints `$_` afterwards; `-a` splits each line into `$F`; and `-l` chomps the newline on the way in and adds it back on the way out — compare the two `puts $_ + "!"` rows, where without `-l` the `!` lands on its own line. Row 8, `-E`, sets the default external encoding, which is why this library runs every example as `ruby -E UTF-8`. Row 9 enables YJIT for the child only; row 10 starts Ruby without RubyGems, so `Gem` is not even defined (and startup is faster); row 11 makes every string literal frozen, the same effect as the `# frozen_string_literal: true` magic comment, but for the whole run. Row 12 asks the compiler to print its instruction sequence — the names show `1 + 2` compiled as `putobject_INT2FIX_1_`, `putobject` (the 2) and `opt_plus`, not folded to 3. Row 13 checks `-v` and `-h` only by their first words, since the rest names a version. Row 14 is `--`, which ends flag parsing so that `-x` reaches `ARGV`; row 15 is `-s`, which turns `-flag=5` on the command line into a global `$flag` — a Perl idea that Python's `-s` has nothing to do with. `-S` looks the script up on `PATH` (so `ruby -S rake` finds the installed `rake`), and `RUBYOPT` holds flags every run should have *(Not machine-checked here.)*.

## Compared with Python

The counterparts line up by row. `-c` is Python's `-e` (row 1); a syntax check is `-m py_compile file` (row 2), which prints nothing on success and a `SyntaxError` on failure; there is no `-w` lint, so row 3 shows the warnings *filter* instead — `-W error` turns a `warnings.warn` into a failing exit, and plain running prints the warning to stderr and continues. Row 4 is `-X dev`, the development mode that switches on extra checks and warnings, next to `-W ignore`. `-m module` (row 5) runs a module as a script, a job Ruby splits between `-r` and `-S`. The letters that collide start at row 6: Python's `-I` means *isolated* — ignore environment variables, the user site directory, and the script's own folder on `sys.path` (`safe_path: True`) — which is why this library runs every twin with it; the include-a-folder job belongs to the `PYTHONPATH` variable. Row 7 has no `-n`/`-p`/`-a`/`-l` at all: the loop over `sys.stdin` is written out, and `line.rstrip()` does what `-l` did. Row 8 is `-X utf8` (UTF-8 mode) beside `sys.stdout.encoding`, which this page's environment already pins to `utf-8`. Row 9: no JIT switch in 3.12, so the twin shows `-O`, the optimizer flag that sets `__debug__` to `False` and removes `assert` statements; the experimental `-X jit` appears only in later interpreters built with it *(Not machine-checked here.)*. Row 10, `-S`, skips the `site` module — the closest thing to `--disable-gems`, since `site` is what puts installed packages on `sys.path`. Row 11 is `-OO`, which additionally strips docstrings, a compile-time switch in the spirit of `--enable=frozen-string-literal`. Row 12 shows constant folding through `co_consts` (`1000 + 2000` became `3000` at compile time, where Ruby left `1 + 2` as two pushes and an `opt_plus`); `python3 -m dis` prints the bytecode, but its text changes with every release, so the page does not key it *(Not machine-checked here.)*. Row 14 needs no `--`: everything after the `-c` string is `sys.argv`, and `sys.argv[0]` is the string `-c`. Row 15 is the false friend: Python's `-s` disables the user site-packages directory. The Python library's [`-c` is not the prompt ↗](https://masiarek.github.io/python-learning-library/02_Projects_and_Environments/dash_c_is_not_the_prompt/index.html) page measures the `-c` flag against the REPL in more detail.

## Try it

1. Feed the two lines `alice 30` and `bob 25` to four one-liners started as child Rubies: `-a -n` printing the second field, `-p` upcasing, `-l -n` appending `!`, and `-a -n` with `BEGIN { }` and `END { }` blocks summing the numbers. Print each command and its output.
2. Run `ruby -w` on a file that reassigns a constant, calls a method with mismatched indentation of `end`, and uses `if x = 1` — collect the three warnings from stderr and print them without the temp-folder path. Then run the same file with `-W0` and show that stderr is empty.

```ruby
# Kata: four one-liners over the same two lines of input, each run as a child
# Ruby, each printing the command and what it produced.
require "open3"

INPUT = "alice 30\nbob 25\n"

def one_liner(flags, code)
  out, = Open3.capture3(RbConfig.ruby, *flags, "-e", code, stdin_data: INPUT)
  puts "ruby #{flags.join(" ")} -e '#{code}'"
  out.each_line { |line| puts "    #{line}" }
end

one_liner %w[-a -n], "puts $F[1]"
one_liner %w[-p],    "$_.upcase!"
one_liner %w[-l -n], 'puts $_ + "!"'
one_liner %w[-a -n], "BEGIN { $sum = 0 }; $sum += $F[1].to_i; END { puts $sum }"
```
