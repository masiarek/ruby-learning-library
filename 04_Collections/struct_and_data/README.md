# Struct is mutable, Data is not

**Level:** 201 · anyone choosing between a Hash, a Struct and a Data for a record

**One line:** `Struct.new(:x, :y)` makes a record you can build positionally or by keyword and then change; `Data.define(:lat, :lng)` makes one you cannot — no setters, frozen instances, and `with` for a changed copy — and both compare by value and pattern-match; Python's three counterparts are `namedtuple`, `@dataclass` and `@dataclass(frozen=True)`.

`Struct.new` returns a class. Its instances take their members positionally or, since 3.2, by keyword; a member left out is `nil`, one too many is an `ArgumentError`; each member has a reader, a writer and an index (`pt[:y]`, `pt[0]`); two instances of the same Struct class with the same values are `==` and `eql?` and hash alike, so a Struct works as a Hash key; and `to_a`, `members`, `to_h`, Enumerable, `deconstruct` and `deconstruct_keys` all come for free. A block given to `Struct.new` adds methods, and `keyword_init: true` forbids the positional form. `Data.define`, added in 3.2, returns a class whose instances are frozen at birth: there are no writers (`c.lat = 5` is a `NoMethodError`, not a `FrozenError` — the method does not exist), `instance_variable_set` hits the freeze, and `with(lat: 9)` is the way to get a changed copy. Construction is stricter — a missing member is `missing keyword`, an extra one `unknown keyword`, and positional arguments are turned into keywords before `initialize` runs, which is why a custom `initialize(deg:)` that calls `super(deg: Float(deg))` normalises both spellings. A Data has `to_h` and `deconstruct_keys` and also `deconstruct`, so it matches array patterns, but it has no `to_a`, no `each` and is not Enumerable. Immutability is shallow: a mutable member is still mutable.

## Reading the output

Rows 1–2: the two spellings of construction, the `nil` for a missing member, and `struct size differs` for one too many.

Rows 3–6: a Struct is mutable through the writer and through `[]`; equal values make equal, alike-hashing instances that work as Hash keys; `to_a`, `members` and `to_h` are the three views; and two *different* Struct classes with the same members are not equal, whatever their values.

Row 7: `in [x, y]` uses `deconstruct` and `in {x:, y:}` uses `deconstruct_keys`, and both match a Struct.

Rows 8–9: a block adds methods; `keyword_init: true` turns the positional call into `wrong number of arguments (given 2, expected 0)`.

Rows 10–11: `Data.define` takes the same two spellings, but a missing member is `missing keyword: :lng`, three positional arguments are one too many, and an unknown keyword is refused.

Rows 12–14 are immutability. There is no `lat=` method; the frozen instance refuses `instance_variable_set`; `with` builds a copy with one member changed and leaves the original alone.

Rows 15–16: equality, `eql?`, `hash` and Hash-key use match the Struct's; `to_a` and `each` do not exist and the class is not Enumerable, but `deconstruct` and `to_h` are there.

Row 17: the array pattern *does* match a Data — it defines `deconstruct` — and so do the hash pattern and the `Coord(lat:, lng:)` form.

Row 18: `Temp.new("35")` and `Temp.new(deg: 12)` both reach `initialize(deg:)`, and both come out as Floats.

Row 19: the Array inside a frozen Data is not frozen; `<<` on it works.

## Compared with Python

The twin puts the same nineteen questions to `namedtuple` and `@dataclass` for the Struct rows and to `@dataclass(frozen=True)` for the Data rows. A `namedtuple` *is* a tuple: immutable (row 3, `AttributeError`), hashable, iterable, equal to any tuple with the same values — including a different namedtuple class (row 6) — and matched by a sequence pattern as well as by `Point(x, y)` (row 7). A plain `@dataclass` is the mutable record: it compares equal only within its own class (row 6), it is *unhashable* by default (row 4: `hash(P(1, 2))` is a `TypeError`, because `eq=True` without `frozen=True` sets `__hash__` to `None`), and `astuple`/`asdict` are its `to_a`/`to_h` (row 5). Missing or extra arguments are `TypeError`s in all three (rows 2, 9, 11), and `kw_only=True` is `keyword_init: true` (row 9). The frozen dataclass is the Data: assignment raises `FrozenInstanceError` (row 12) — but `object.__setattr__` walks straight past the freeze (row 13), which has no Ruby counterpart, since a Ruby freeze is enforced by the object — `replace` is `with` (row 14), it is hashable (row 15), and it is not iterable (row 16). Its pattern matching is class-only: `case [lat, lng]` does not match a dataclass (row 17) where Ruby's `in [lat, lng]` does. Normalisation goes in `__post_init__`, and inside a frozen class it needs `object.__setattr__` too (row 18). Immutability is just as shallow (row 19), and a frozen dataclass holding a list is unhashable for the same reason the list is.

```ruby
# Kata: an immutable Money value with Data.define -- a normalising initialize,
# a parser, an operator that returns a new object, `with` for a change, and
# use as a Hash key.

Money = Data.define(:cents, :currency) do
  def self.parse(text)                       # "12.50 eur" -> Money
    amount, currency = text.split
    new(cents: (Float(amount) * 100).round, currency: currency)
  end

  def initialize(cents:, currency: "EUR") = super(cents: Integer(cents), currency: currency.upcase)

  def +(other)
    raise ArgumentError, "#{currency} + #{other.currency}" unless currency == other.currency
    with(cents: cents + other.cents)
  end

  def to_s = format("%.2f %s", cents / 100.0, currency)
end

a = Money.parse("12.50 eur")
b = Money.new(cents: "250")
puts "a = #{a}, b = #{b}"
puts "a + b = #{a + b}; a is still #{a}"
puts "a == Money.new(1250)? #{a == Money.new(1250)}  (positional, currency defaulted)"
puts "as a Hash key: #{{a => :paid}[Money.new(cents: 1250, currency: 'eur')].inspect}"
begin
  a + Money.new(cents: 100, currency: "usd")
rescue ArgumentError => e
  puts "mixed currencies: #{e.class}: #{e.message}"
end
begin
  a.cents = 0
rescue NoMethodError => e
  puts "a.cents = 0: #{e.class}"
end
puts "inspect: #{a.inspect}"
```
