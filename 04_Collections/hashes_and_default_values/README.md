# A missing key is nil, and `Hash.new([])` shares its default

**Level:** 101 · a Python programmer meeting Ruby's dict

**One line:** `h[:zz]` is `nil` where `d["zz"]` raises `KeyError`; `fetch` is the raising form; `Hash.new(0)` returns a default without storing it, `Hash.new { |h, k| h[k] = [] }` stores what its block assigns, and `Hash.new([])` hands every key the same one array — Python's `dict.get`, `Counter`, `defaultdict` and `dict.fromkeys(keys, [])`, in that order.

A Ruby `Hash` is Python's `dict`: keys map to values, insertion order is kept (Ruby since 1.9, Python since 3.7 *(Not machine-checked here.)*), and any object can be a key — Ruby hashes it with `hash` and compares with `eql?`, Python with `__hash__` and `__eq__`. Three things differ at the surface. Keys are usually Symbols: `{a: 1}` has the Symbol key `:a`, `{"a" => 1}` has a String key, and `{"a": 1}` — the spelling a Python hand types — makes a Symbol key too. A missing key answers `nil`, and `fetch` is the method that raises (`KeyError`, with a message naming the key) or takes a default. And a Hash carries its own default: a value given to `Hash.new` is returned for every missing key but never stored, a block given to `Hash.new` runs for every missing key and stores whatever it assigns, and a mutable value given to `Hash.new` is one object shared by every miss — the trap the title names. One more thing to know before the Object Model chapter takes it further: a String key is copied and frozen on the way in, so mutating the variable you inserted with does not corrupt the hash.

## Reading the output

Rows 1–2: the keys come back in the order they went in, and the three literal spellings give Symbol, String, Symbol.

Rows 3–5 are the missing-key contract: `[]` answers `nil`, `fetch` raises `KeyError` with `key not found: :zz`, and `fetch` with a second argument or a block answers that instead.

Rows 6–8 are `Hash.new(0)`, the counting idiom: `counts[c] += 1` reads the default `0`, adds one and stores the result. Row 7 shows the default is *returned, not stored* — reading `:zz` gives `0` and the size stays 4 — and row 8 shows `fetch` ignores the default altogether.

Rows 9–10 are the block form, the grouping idiom: the block receives the hash and the key and stores an empty array under it, so `groups[w.size] << w` works on the first word of each length. Because the block assigns, merely *reading* `groups[99]` stores a key (row 10) — the opposite of row 7.

Rows 11–12 are the trap and the idiom. `Hash.new([])` evaluates `[]` once; `t[:a] << 1` appends to that one shared array and stores nothing, so `t` is still `{}` and every missing key now answers `[1, 2]`. The idiom that stores is `u[:a] ||= []` (or the block form of row 9).

Rows 13–15: `dig` walks nested keys and indexes and answers `nil` at the first miss; `transform_keys` and `transform_values` rebuild the hash; `to_h` goes from pairs to a hash, `to_a` back, and `to_h` with a block does both in one step.

Rows 16–17: `each` yields one two-element Array per entry; a block with two parameters auto-splats it into `k, v`. `key?` asks about keys and `value?` about values.

Rows 18–20 are about keys as objects. The String key was duplicated and frozen on insertion, so appending to the original variable did not change the key. `1` and `1.0` are two keys, because `1.eql?(1.0)` is false. `compare_by_identity` switches a hash from `eql?` to `equal?`, so two equal but distinct Strings become two keys.

Rows 21–22: `merge` takes a block to resolve a key present on both sides; `delete` returns the removed value, or `nil` for a key that was not there.

## Compared with Python

The twin asks a `dict`, a `Counter` and a `defaultdict` the same twenty-two questions. Python has one string type and no Symbol, so row 2 has nothing to distinguish. A missing key *raises* `KeyError` (row 3); plain indexing is already Ruby's `fetch`, and `get` is Ruby's `[]` (rows 4–5). `Counter` is `Hash.new(0)` exactly — a read of a missing key answers `0` without storing it (rows 6–7) — but `defaultdict` is the block form: its read of a missing key stores the factory's value (rows 8 and 10), and `get` skips the factory. The shared-default trap is spelled `dict.fromkeys(keys, [])` (row 11): one list under every key. `setdefault` is `||=` (row 12); there is no `dig` (row 13, a five-line helper); comprehensions are the `transform_*` methods (rows 14–15); `items()` yields tuples, which `for k, v` unpacks (row 16). Rows 18–20 are where the object models diverge: a `str` is immutable so there is nothing to copy, and a `list` key is a `TypeError`; `1` and `1.0` are one key, because `1 == 1.0` and they hash alike; and there is no identity mode for a dict — keying by `id(obj)` is the workaround *(Not machine-checked here.)*. `|` merges (row 21) with the right side winning and no block to say otherwise; `pop` with a default is `delete` (row 22), and `pop` without one raises.

```ruby
# Kata: count words with Hash.new(0), group the words by their count with
# Hash.new { |h, k| h[k] = [] }, then print the groups from the most frequent down.

text = "the cat and the dog and the bird"
counts = Hash.new(0)
text.split.each { |word| counts[word] += 1 }
puts "counts:   #{counts.inspect}"

by_count = Hash.new { |h, k| h[k] = [] }
counts.each { |word, n| by_count[n] << word }
puts "by_count: #{by_count.inspect}"

by_count.keys.sort.reverse.each do |n|
  puts "#{n} x  #{by_count[n].sort.join(', ')}"
end

by_count[99]
puts "reading by_count[99] stored a key: #{by_count.keys.inspect}"
puts "counts['zzz'] did not: #{counts['zzz']} and #{counts.keys.inspect}"
```
