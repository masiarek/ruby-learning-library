# Bang means dangerous, question mark means predicate

**Level:** 101 · a first-week reader who writes Python

**One line:** A trailing `!` marks the more dangerous of two versions of a method — usually the one that changes its receiver, and several of those return `nil` when nothing changed — and a trailing `?` marks a method that answers a yes/no question.

Ruby lets `?` and `!` end a method name, and the community uses them as signals. `?` is the easy one: `empty?`, `zero?`, `include?`, `frozen?` answer a question and return `true` or `false`. `!` is subtler. It does not mean "mutates" — `<<`, `push`, `pop` and `delete` all mutate without it — it means "the more dangerous of these two"; when a method comes in a pair, the bang version is the one that changes the receiver (`sort!`), raises instead of returning nil, or, for `exit!`, skips the clean-up handlers. Several bang methods on `String` and `Array` (`strip!`, `uniq!`, `sub!`, `upcase!`, `flatten!`, `compact!`) also return `nil` when they had nothing to do, so a chain like `s.strip!.upcase` works on one input and raises `NoMethodError` on another.

## Reading the output

Rows 1 and 2 are the pair every reader meets first: `sort` returns a new array and leaves `a` alone; `sort!` sorts `a` in place and returns `a` itself (`r.equal?(a)` is true), so it chains. Row 3 is the trap: `uniq!`, `strip!`, `sub!`, `upcase!`, `flatten!` and `compact!` return `nil` when nothing changed, and the value only when something did. Row 4 shows the consequence — `"abc".strip!.upcase` raises `NoMethodError: undefined method 'upcase' for nil` — and the fix, which is to chain the non-bang versions.

Row 5 is the `?` convention in action; row 6 shows the characters are simply part of the name (`method(:ready?).name` is `:ready?`). Row 7 is the case that proves `!` is about danger, not mutation: two child Rubies each register an `at_exit` handler and print "exiting"; `exit` runs the handler and exits 0, `exit!` skips it — and its default status is 1. Row 8 is the other half of the rule: `<<`, `push` and `pop` change the array without any bang, because they have no gentler twin to be contrasted with.

## Compared with Python

Python has no naming convention for danger; it has a *return* convention. A method that changes its receiver returns `None` — `list.sort()`, `append`, `extend`, `reverse`, `clear` — and the copying version is a separate function (`sorted`, `reversed`). Rows 1 to 4 line up with Ruby's exactly: `sorted(a)` copies, `a.sort()` mutates and returns `None`, and chaining it (`a.sort().append(1)`) fails with `AttributeError` on `None` the way Ruby's chain failed on `nil`. The difference is that Python's `None` comes back *always*, not only when nothing changed, so there is nothing to signal (row 3): `str` is immutable, so `strip()` and `upper()` always return a string. Row 5: predicates are `is_`/`has_` names (`isalpha`, `isdigit`) or plain expressions (`len(x) == 0`, `x in y`), and row 6 shows `def ready?():` does not parse. Row 7: `sys.exit()` runs `atexit` handlers, `os._exit(0)` skips them — the same pair, without the punctuation to warn you. Row 8: `append` returns `None`, `pop` returns the element; no rule tells you which.

```ruby
# Kata: normalize a string in place without chaining bang methods, then show
# why the chained version is a trap.
def normalize!(s)
  s.strip!
  s.downcase!
  s
end

def normalize_chained!(s)
  s.strip!.downcase!
end

a = "  MiXed  "
puts "1. normalize!(\"  MiXed  \")           -> #{normalize!(a).inspect}, and a is now #{a.inspect}"
b = "clean"
puts "2. normalize!(\"clean\")               -> #{normalize!(b).inspect} (nothing changed, still returns the string)"
c = "clean"
begin
  normalize_chained!(c)
rescue NoMethodError => e
  puts "3. normalize_chained!(\"clean\")       -> #{e.class}: #{e.message}"
end
d = "  MiXed  "
puts "4. normalize_chained!(\"  MiXed  \")   -> #{normalize_chained!(d).inspect} (works only because strip! changed something)"
e = " mixed "
puts "5. normalize_chained!(\" mixed \")     -> #{normalize_chained!(e).inspect} (strip! changed it, downcase! did not, and e is #{e.inspect})"
```
