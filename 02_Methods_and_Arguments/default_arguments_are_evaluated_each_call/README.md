# Default arguments are evaluated on every call

**Level:** 201 · a Python programmer who has met the mutable-default trap

**One line:** A Ruby default is an expression that runs each time the method is called without that argument, so `def f(a = [])` hands out a fresh array on every call, a default may use an earlier parameter, and it may even count the calls.

A default in a Ruby `def` is not a value attached to the method; it is code that belongs to the method body and runs, in the method's own scope, whenever the caller leaves that argument out. Three things follow. A `[]` or `{}` default is a *new* object on each call, so nothing accumulates between calls. A default can read the parameters to its left — `def rect(w, h = w * 2)` — because those have already been bound when it runs (and it cannot read one to its right, which is not bound yet). And a default can have side effects: a counter in a default advances once per call that uses it, and an explicit argument skips the expression entirely.

## Reading the output

Row 1 is the whole point: three calls to `add_item` without a list give `[:a]`, `[:b]`, `[:c]` — three arrays. Row 2 shows there is nothing to share: `Method#parameters` reports `[:opt, :list]` and no value, because the default is an expression, not an object stored anywhere. Row 3 is the `list = nil; list ||= []` idiom a Python reader may reach for out of habit; it works, and it is unnecessary.

Row 4: `rect(3)` computes `h` from `w`, and `chain(1)` evaluates its defaults left to right, each seeing the last. Row 5 is the boundary: `def later(a = b, b = 1)` *defines* fine, but calling it raises `NameError` because `b` is not bound yet when `a`'s default runs — Ruby fails at call time, not at definition time. Row 6 makes the timing visible: `tick`'s default increments a counter, so three calls give 1, 2, 3; `tick(10)` skips the default, and the next bare call gives 4. Row 7 shows *when* the expression runs — during the call, printed inline before the result, and not at all for `side(2)`.

## Compared with Python

Python evaluates a default exactly once, when the `def` statement runs, and stores the resulting object on the function. Row 1 is the consequence every Python programmer learns the hard way: one list, shared by every call, so the three calls return `['a', 'b', 'c']` three times. Row 2 shows where it lives — `add_item.__defaults__` — and row 3 the standard fix, a `None` sentinel replaced inside the body, which is exactly what Ruby does for you. Rows 4 and 5 fail at *definition* time with a `NameError`: when the default expression runs, no parameter exists yet, neither earlier nor later. Row 6: the counter advances once, at `def`, so `tick()` returns 1 forever; row 7 prints "(default evaluated now)" before the `def` finishes and never again. The Python page on this trap is the reverse hub in this library's last chapter, linked below.
