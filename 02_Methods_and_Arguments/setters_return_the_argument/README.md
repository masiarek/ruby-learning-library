# A setter returns its argument, not its body

**Level:** 201 · a reader who has written a `@property` setter in Python

**One line:** `obj.x = 5` is a call to the method `x=`, but as an expression it evaluates to 5 whatever the method body returns — only `obj.send(:x=, 5)` shows the body's value — and the same holds for `[]=`, `+=` and `||=`.

A method whose name ends in `=` is a setter, and `obj.x = v` is sugar for calling it. Ruby makes assignment an expression, and it decides what that expression is worth *before* the method runs: the right-hand side. So the value of `obj.x = 5` is 5 even if `def x=(v)` returns `:ignored`, chained assignment `a = obj.x = 9` gives `a` the 9, and `obj.x = 1, 2` passes the Array `[1, 2]`. The only way to see what the body returned is to call the method without the sugar — `send(:x=, 5)` or `method(:x=).call(5)`. Inside the class, the sugar needs an explicit receiver (`self.x = v`), because a bare `x = v` is a local variable. There is no universal assignment hook as in Python's `__setattr__`; a class defines each setter, with `attr_writer`/`attr_accessor` writing the plain ones, and `method_missing` can catch any name that ends in `=`.

## Reading the output

Row 1 is the claim: `(b.x = 5)` is 5, and `b.x` reads back 5, while `:ignored` went nowhere. Row 2 calls the same method without the sugar and gets `:ignored` both ways. Row 3: `attr_writer :w` writes a setter and no reader, so `b.w = 3` works and `b.w` is a `NoMethodError`. Row 4: with two values on the right, the setter receives one Array. Row 5 is the trap shared with the previous lesson — `x = value` inside the class is a local; `self.x = value` is the call. Row 6: chained assignment passes the 9 along, not `:ignored`. Row 7: `[]=` obeys the same rule (`(b[:k] = "v")` is `"v"`, `send(:[]=, …)` shows `:ignored_too`). Row 8: `+=` and `||=` are read-then-write through the reader and setter pair, and evaluate to the new value. Row 9 is the closest thing to a universal hook: `Bag#method_missing` accepts any `name=`, stores the value, and — like every setter — its return value is invisible to `bag.color = "red"` and visible to `send`.

## Compared with Python

Python draws the line one step earlier: assignment is a *statement*, so `(b.x = 5)` does not compile at all (row 1, "cannot assign to attribute here"), and the question "what does the assignment evaluate to?" cannot be asked. The setter's return value is just as invisible, and just as reachable by calling the function directly: `Box.x.fset(b, 6)` returns `"ignored"` (row 2), while the built-in `setattr` returns `None`. Row 3 is the `attr_writer` twin, a `property(fset=…)` with no getter, which raises `AttributeError` on a read. Row 4 agrees exactly, with a tuple for the Array. Row 5 is the shared trap; row 6 shows chained assignment allowed as a statement. Rows 7 and 8 match Ruby's `[]=` and `+=`, minus the value. Row 9 is where Python has more: `__setattr__` intercepts *every* attribute assignment on the object, where Ruby has to define each setter or catch names ending in `=` with `method_missing`.

# Kata: a setter that clamps what it stores. The assignment still evaluates
# to the argument; only send shows what the body returned.
class Thermostat
  attr_reader :target

  def target=(degrees)
    @target = degrees.clamp(10, 30)
  end
end

t = Thermostat.new
r = (t.target = 99)
puts "1. r = (t.target = 99)      -> r is #{r} (the argument, unclamped)"
puts "2. t.target                 -> #{t.target} (the setter clamped what it stored)"
puts "3. t.send(:target=, 99)     -> #{t.send(:target=, 99)} (the body's value, visible only through send)"
