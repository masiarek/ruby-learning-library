# Arguments: positional, keyword, splat and block

**Level:** 201 · a reader who knows Python's `*args` and `**kwargs`

**One line:** A Ruby parameter list has eight kinds of slot — required, optional, `*rest`, post-required, `key:`, `key: default`, `**opts` and `&blk` — plus `...` and anonymous forwarding — and a Hash argument never turns into keywords by itself.

The positional part of a Ruby signature is matched by *position only*: a name in a `def` is never something a caller can say, so `two(b: 2, a: 1)` does not fill `a` and `b`, it passes one Hash. Keywords are a separate channel, declared with a trailing colon (`k:` required, `d: 4` defaulted, `**opts` for the rest), and the two channels do not leak into each other (the Ruby 3.0 "keyword separation" *(Not machine-checked here.)*): `kw({k: 1})` is a positional Hash and fails, `kw(**{k: 1})` splats it into keywords and works. A required positional may even come *after* the splat (`def f(a, b = 2, *rest, z)`), which Python cannot express. The block is its own slot (`&blk`), and `...` forwards all three channels at once; a bare `*`, `**` or `&` in the parameter list can be forwarded without a name (new in Ruby 3.2 *(Not machine-checked here.)*). When a call does not fit, the error is an `ArgumentError` with one of three stable messages.

## Reading the output

Row 1 is the positional channel in full: with two arguments, `a` and the post-required `z` are filled first and `b` keeps its default; with five, `b` takes the second, `z` the last, and `*rest` whatever is left. Row 2 is the same signature as `Method#parameters` reports it — `:req`, `:opt`, `:rest`, `:req` — and row 3 adds the keyword channel: `:keyreq`, `:key`, `:keyrest`. Rows 4 to 6 are the block slot and forwarding: `&blk` reifies the block, `...` passes positionals, keywords and the block on untouched, and the anonymous `*`, `**`, `&` do the same with no names to invent (their `parameters` entries are literally `:*`, `:**` and `:&`).

Rows 7 to 9 are the three messages to recognise: "wrong number of arguments (given 1, expected 2+)", "missing keyword: :k", "unknown keyword: :z". Row 10 is the keyword-separation rule: a braced Hash is one positional argument, so `kw({k: 1})` fails with a message that even names the missing keyword, while `**` splats it into the keyword channel. Row 11 is its mirror image: positionals have no names, so `two(b: 2, a: 1)` is one Hash where two arguments were expected, and `pos(a: 1)` receives that Hash as `a`. Row 12: `arity` is the count of required arguments, negative when the method takes optional ones (`-3` for `f` means at least two, `-(2+1)`); a required keyword counts as one.

## Compared with Python

Python's positional and keyword channels overlap: any parameter declared without a marker can be passed either by position or by name, so `two(b=2, a=1)` works (row 11) — and you need `/` to forbid it (`pos_only`). A bare name after `*rest` is not a post-required positional but *keyword-only*, which is why the same `def f(a, b=2, *rest, z)` rejects `f(1, 9)` in row 1 and needs `z=5` — Ruby's post-required positional has no Python spelling. Rows 3 and 10 agree with Ruby: keyword-only after `*`, `**opts` for the rest, a dict is one positional argument and `**` splats it. Python has no block slot (a callable is an ordinary argument, rows 4 and 5) and no anonymous forwarding: `*args, **kwargs` must be named to be passed on (row 6). Every failed call is a `TypeError`; the twin prints only the type, because CPython rewords these messages between releases. There is no `arity`; `inspect.signature` gives the parameters and their kinds (rows 2 and 12).
