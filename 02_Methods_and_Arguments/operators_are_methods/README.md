# Operators are methods, except the ones that are not

**Level:** 201 · a reader who has written `__add__` in Python

**One line:** `+`, `-@`, `[]`, `[]=`, `<=>`, `<<` and even `!` are ordinary methods you define with `def`, and `1 + 2` is `1.+(2)` — but `&&`, `||`, `=`, `?:`, `..`, `and`, `or` and `not` are syntax and cannot be defined or looked up.

When Ruby sees `a + b` it sends the message `+` to `a` with `b` as the argument; the operator table is just spelling rules for method names. So a class defines `+` with `def +(other)`, unary minus as `def -@`, indexing as `def []` and `def []=`, and gets the whole family of comparisons by defining `<=>` and including `Comparable`. Even `!` is a method (`BasicObject#!`), which is why `!obj` and `not obj` can be overridden. The exceptions are the operators whose meaning depends on *not* evaluating an operand or on the parser: short-circuit `&&`/`||` (and their word forms), assignment `=`, the conditional `?:`, and ranges `..`. Those are not messages; `1.method(:"&&")` is a `NameError` and `def &&` does not parse. One more thing to know from Python: a reflected operation (`2 * vec`) does not look for a `__rmul__`; Ruby's `Integer#*` asks the argument for `coerce` instead.

## Reading the output

Row 1 is the claim at its plainest: `1 + 2`, `1.+(2)` and `1.send(:+, 2)` are one call, owned by `Integer`. Rows 2, 3 and 6 are `Vec`'s own `+`, `-@` and `<<`. Row 4 is `[]` and `[]=` — with a detail from the setters lesson: `v[1] = 9` evaluates to 9 no matter that the body returned `:ignored`. Row 5 is the payoff of `<=>`: one definition plus `include Comparable` gives `<`, `==`, `!=`, `min`, `clamp` and the rest. Row 7 shows `!` really is a method: `!v`, `not v` and the explicit `v.!` all run our definition and return a String, which no Python `not` could do.

Row 8 is the reflected case: `v * 2` works because `Vec#*` exists, but `2 * v` fails with `TypeError: Vec can't be coerced into Integer` — `Integer#*` does not know about `Vec` and asks it for `coerce`, which the numbers chapter covers. Row 9 is the boundary: `&&` is not a method name — looking it up is a `NameError`, defining it is a `SyntaxError`. Row 10 sorts a fixed list of operator spellings by `1.respond_to?`: everything from `+` to `===` is a method on Integer; `&& || .. and or not =` are not.

## Compared with Python

Python's model is the same one with different spelling: an operator is a call to a "dunder" hook — `__add__`, `__neg__`, `__getitem__`, `__setitem__`, `__eq__`, `__lt__`, `__lshift__` — and row 1 shows `1 + 2` as `(1).__add__(2)`. The differences are in the corners. Row 4: `v[1] = 9` is a statement in Python, so `__setitem__`'s return value simply vanishes; Ruby's assignment is an expression that evaluates to the right-hand side. Row 5: there is no `<=>`; `__eq__` and `__lt__` plus `functools.total_ordering` give the family, and without `__lt__` a `<` is a `TypeError`. Row 7: `not v` calls `__bool__`, but can only ever produce a bool — Ruby's `!` is a real method that returned a String. Row 8 is the reflected operation Ruby lacks: `2 * v` finds `__rmul__`. Rows 9 and 10 draw the same boundary as Ruby: `and`, `or`, `not` and `=` are keywords and syntax with no hook, while `&` has `__and__`.

# Kata: a Money class whose +, unary -, and <=> are methods, with Comparable
# supplying <, ==, between? and clamp from the one <=> definition.
class Money
  include Comparable
  attr_reader :cents

  def initialize(cents) = @cents = cents
  def +(other) = Money.new(cents + other.cents)
  def -@ = Money.new(-cents)
  def <=>(other) = cents <=> other.cents
  def to_s = format("$%.2f", cents / 100.0)
  def inspect = to_s
end

a, b, c = Money.new(500), Money.new(1250), Money.new(99)
puts "1. a + b                    -> #{a + b}"
puts "2. -a                       -> #{-a}"
puts "3. [b, a, c].sort           -> #{[b, a, c].sort.inspect}"
puts "4. [b, a, c].max            -> #{[b, a, c].max}"
puts "5. a < b, a == Money.new(500), a != b -> #{a < b}, #{a == Money.new(500)}, #{a != b}"
puts "6. c.between?(a, b)         -> #{c.between?(a, b)}; c.clamp(a, b) -> #{c.clamp(a, b)}"
puts "7. Money.instance_method(:<).owner -> #{Money.instance_method(:<).owner} (Comparable wrote < from <=>)"
