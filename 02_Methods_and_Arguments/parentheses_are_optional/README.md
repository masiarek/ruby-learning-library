# Parentheses are optional, but the space is not

**Level:** 101 · a first-week reader who writes Python

**One line:** Ruby lets you leave the parentheses off a call and off a `def`, so a bare name *is* a call — and the space before a `(` decides whether the parentheses belong to the call or to the expression.

Ruby decides what a bare identifier means while it parses: if an assignment to that name appeared earlier in the same scope, the name is a local variable; otherwise it is a method call on the implicit `self`. Writing `foo()` or `self.foo` always means the method. A `def` may drop its parentheses too (`def f a, b`). The price of all this freedom is that whitespace carries meaning: in `puts (1+2)*3` the space makes `(1+2)` a grouped expression, so `puts` receives 9, while `puts(1+2)*3` gives the parentheses to the call, so `puts` receives 3 and its result — `nil` — is multiplied. The same goes for a unary minus and a splat: `p -1` prints -1 and `p - 1` subtracts from the result of `p`. The `-w` flag warns about the minus and the star, but says nothing about the grouped expression.

## Reading the output

Rows 1 and 2 are the plain freedom: `puts "x"` and `def f a, b` both parse. Rows 3 to 6 are the rule for a bare name: with no local called `greeting`, the bare name calls the method; once `greeting = "the local"` has run, the bare name is the variable, and only `greeting()` or `self.greeting` reaches the method again.

Rows 7 and 8 differ by one space. `puts (1+2)*3` prints 9: the parentheses group `1+2` and the whole product is the argument. `puts(1+2)*3` prints 3 and then raises `NoMethodError: undefined method '*' for nil`, because the parentheses were the argument list, `puts` returned `nil`, and `nil * 3` has nowhere to go. Row 9 starts a child Ruby with `-w` on row 7's spelling and captures an empty stderr: the 4.0 parser accepts the grouped expression without comment, so the flag will not catch this one for you.

Rows 10 to 12 do the same with a minus. `p -1` is `p(-1)`; row 11 shows that `-w` *does* warn here — "ambiguous first argument; put parentheses or a space even after `-` operator" — and `p - 1` is `p() - 1`, which is `nil - 1`. Rows 13 and 14: `rest *[1, 2]` is a splat argument, again with a `-w` warning, whereas `rest * [1, 2]` would be multiplication.

## Compared with Python

Python has no bare-name calls: parentheses are the call operator, a name is a reference, and whitespace before `(` is never significant. So `print "x"` and `def f a, b:` fail to compile (rows 1 and 2), the bare `greeting` is a function object (row 3), and once the name is rebound to a string, `greeting()` is a `TypeError` because the function is simply gone (rows 4 to 6). Rows 7 and 8 are the interesting pair: `print (1+2)*3` and `print(1+2)*3` are the *same* program in Python — both print 3 and then fail on `None * 3` — and row 9 proves it by compiling both spellings to identical bytecode. Ruby's row 8 and Python's rows 7 and 8 are the same mistake with the same shape of error: a printing function returns nothing, and arithmetic on nothing fails. Rows 10 to 14 close the loop: `p -1` and `p - 1` are both subtraction in Python, and `*` unpacks only inside the call's parentheses.
