# `puts` adds a newline, `print` does not, `p` shows `inspect`

**Level:** 101 · anyone whose fingers type `print(...)` and want to know which of Ruby's four to reach for

**One line:** `puts` writes `to_s` plus a newline it does not double, flattening arrays, printing `nil` as an empty line and an empty array as nothing; `print` writes `to_s` and nothing else; `p` writes `inspect` and returns its argument; `pp` is `p` that wraps at 80 columns — where Python has one `print` with `sep`, `end` and `file` keywords, and `repr`/`pprint` for the rest.

All four are `Kernel` methods that write to `$stdout`, which is why the program below can swap `$stdout` for a `StringIO`, run each call, and show the exact characters it wrote. `puts` calls `to_s` on each argument and adds a newline only when the string does not already end in one; an array is flattened and written one element per line, `nil` and an empty array become an empty line, and it returns `nil`. `print` calls `to_s` and adds nothing. `p` calls `inspect` — the debugging view, quotes and all — and returns what it was given (one object, or an array of several), which makes `p` safe to wrap around any expression in a chain. `pp` is `p` with line-wrapping at the terminal's width, or 80 columns when the output is not a terminal — it reads `COLUMNS` in that case, which the program clears so the run is the same everywhere. `$stdout.write` is the primitive under them all and returns the number of *bytes* it wrote; `printf` is `format` plus `write`; `<<` chains. `warn` and `$stderr.puts` write to `$stderr`, the stream the library's runner does not record, so the program captures it the same way.

## Reading the output

Rows 1–7 are `puts`: a newline added (row 1) but not doubled (row 2), each argument on its own line (row 3), arrays flattened (row 4), `nil` and no argument at all each producing one empty line (rows 5 and 7) — while an empty array writes nothing at all, not even a newline (row 6). Rows 8–9 are `print`: no separator, no newline, and `nil.to_s` is the empty string, so `print nil, 1.0` writes just `1.0`. Rows 10–14 are `p`: it writes `inspect`, so a string keeps its quotes (row 10); several arguments become several lines (row 11) and the return value is the array of them (row 12); one argument comes back as itself and a bare `p` returns `nil` (row 13); `puts` always returns `nil` (row 14). Rows 15–17 fix the rule: `puts`, `print` and `"#{}"` interpolation use `to_s`, `p` uses `inspect` — and `puts [obj]` flattens, so it still uses `to_s` of the element, while `p [obj]` shows `Array#inspect`, which calls `inspect` on each element. Rows 18–21 are `pp`: `p h` is one line of 175 characters with its newline, `pp h` wraps it at 80 columns and keeps the Hash's insertion order (`name` first), and it returns the same object. Rows 22–25 are the primitives: `write` counts bytes, so the six bytes of `"café\n"` return 6; it accepts several arguments; `printf` formats then writes; `<<` returns the stream so it chains. Rows 26–27: `warn` and `$stderr.puts` both landed in the swapped-in `$stderr`, and `warn` with two arguments wrote two lines, as `puts` would.

## Compared with Python

Python has one function. `print(*args, sep=" ", end="\n", file=sys.stdout, flush=False)` writes `str()` of each argument joined by `sep` and followed by `end`, so `print(1, 2)` stays on one line where `puts 1, 2` makes two (row 3), `print([1, [2, 3]])` writes the list's `repr` where `puts` flattens (row 4), and `print(None)` writes the word `None` where `puts nil` writes an empty line (row 5). `print("a\n")` adds its `end` regardless, giving a blank line, where `puts` checks for one first (row 2). Ruby's `print` is `print(..., sep="", end="")` (row 8). There is no `p`: the spelling is `print(repr(x))`, and `print` returns `None` whatever it printed (rows 10–14) — so the "wrap it in `p` and look" trick becomes `print(repr(x)); x` or an f-string with `!r`. The `to_s`/`inspect` pair is `__str__`/`__repr__` (rows 15–17), with the same rule that containers use `repr` of their elements — the Python library's [`repr` is not `str` ↗](https://masiarek.github.io/python-learning-library/01_Text_and_Bytes/repr_is_not_str/index.html) measures it. `pprint.pprint` wraps at `width=80` but *sorts dict keys by default* (row 20 shows `address` first); pass `sort_dicts=False` for insertion order (row 19), and it returns `None` (row 21). `sys.stdout.write` returns the number of *characters* — 5 for `"café\n"` where Ruby returned 6 bytes (row 22) — takes one string (row 23), and cannot chain (row 25). Standard error is `print(..., file=sys.stderr)`, and several arguments stay on one line there too (rows 26–27); [Standard in, standard out, and pipes ↗](https://masiarek.github.io/python-learning-library/01_Text_and_Bytes/stdin_stdout_and_pipes/index.html) is the Python library's page on the three streams.

```ruby
# Kata: reimplement puts on top of $stdout.write -- flatten arrays, one item per
# line, nil becomes an empty line, and a string that already ends in a newline
# gets no second one -- then check it against the real puts on several inputs.
require "stringio"

def my_puts(*args)
  args = [""] if args.empty?
  args.flatten.each do |item|
    text = item.nil? ? "" : item.to_s
    text += "\n" unless text.end_with?("\n")
    $stdout.write(text)
  end
  nil
end

def capture
  saved, $stdout = $stdout, StringIO.new
  yield
  $stdout.string
ensure
  $stdout = saved
end

inputs = [["a"], ["a\n"], [1, 2], [[1, [2, 3]]], [nil], [[]], [], [:sym, 1.5]]
inputs.each do |args|
  mine = capture { my_puts(*args) }
  real = capture { puts(*args) }
  puts format("%-16s mine=%-16s real=%-16s same=%s", args.inspect, mine.inspect, real.inspect, mine == real)
end
```
