# `Time` is an instant, `Date` is a calendar day

**Level:** 201 · anyone about to do arithmetic on a timestamp, or to parse one

**One line:** a `Time` is a point on the timeline with an offset attached — add seconds, subtract two for a Float — and a `Date` is a day on the calendar with no clock: add days with `+`, months with `>>` (which clamps January 31 to February 29), and subtract two for a Rational; Python's `datetime` covers both jobs with `timedelta` for arithmetic, has no month step, and splits its objects into aware and naive instead of UTC and local.

`Time.utc(y, m, d, h)` makes an instant flagged UTC; `Time.new(y, m, d, h)` makes the same wall-clock reading in the local zone, which is whatever `TZ` says — this program pins `ENV["TZ"] = "UTC"` before the first `Time` so its local time *is* UTC and the output cannot depend on the machine. `Time.new(..., in: "+02:00")` and `getlocal("+02:00")` give a fixed offset without a zone database. `+`/`-` with a number move by seconds (fractions kept), `-` between two Times is a Float of seconds, and `==` compares the instant, so a `+02:00` reading of 14:00 equals the UTC 12:00. `strftime` is Ruby's own implementation — `%-d` and `%e` work everywhere — and since Ruby 3.4 `iso8601`/`xmlschema` are core; the class-method parsers `Time.parse`, `Time.iso8601` and `Time.strptime` still come from `require "time"`, though `Time.new` itself parses a String since 3.2. `Date` (from `require "date"`) is the calendar: `+ n` is days, `>> n` and `<< n` are months with end-of-month clamping, `Date - Date` is a Rational, `leap?`, `valid_date?`, `wday`/`cwday`/`yday`/`cweek`, negative day numbers counting from the end, and Ranges of Dates. `DateTime` is a `Date` with a clock; the documentation steers you to `Time` instead. *(Not machine-checked here.)*

## Reading the output

Rows 1–3: the instant prints as `2024-02-29 12:00:00 UTC`, adding 86400 gives March 1st, the difference is the Float `86400.0`, and `+ 0.5` keeps the half second. Rows 4–7 are the formatters: `strftime`, including Ruby's own `%-d` and `%e`; `iso8601` printing `Z` for UTC, with `iso8601(3)` for milliseconds; and `to_i`/`to_f`/`to_r` for seconds since 1970. Row 8 is the local/UTC flag: `Time.at(0)` is local — under `TZ=UTC` it prints `+0000` rather than `UTC` and `utc?` is false — and `.utc` re-flags it. Rows 9–11 are offsets: `Time.new` without a zone is local and equals `t` because the local zone here is UTC; with `in: "+02:00"` the same digits are two hours earlier as an instant (`getutc` shows 10:00, the offset is 7200 seconds), so `== t` is false; `getlocal("+02:00")` shows `t` as 14:00 and `== t` is true, because it *is* `t`. Row 12: `<=>`, `==` and `eql?` compare instants; `equal?` is identity. Row 13 is a surprise worth knowing: `Time.utc(2024, 2, 30)` rolls over to March 1st without complaint, while hour 25 raises `ArgumentError`. Rows 15–17 are parsing: `Time.parse` appears only after `require "time"`, `Time.iso8601` honours the offset, `Time.strptime` gives local time, and `Time.new("...")` parses a String. Rows 18–19 are the `Date` claim: `+ 1` is a day, `>> 1` from January 31st is February **29th** (clamped, and 2024 is a leap year), `>> 13` is 2025-02-28, and the difference of two Dates is `(30/1)`, a Rational. Rows 20–24: the three parsers, `leap?` for 2024/2100/2000 (`true false true`), `valid_date?` false for February 30th and `Date::Error: invalid date` when you build it anyway, the four day numbers with `Date::DAYNAMES` for the name, `Date.new(2024, 2, -1)` for the last day of a month, and Ranges and `step`. Row 25 converts both ways. Row 26 shows `DateTime` exists and is a `Date`. Row 27: `Time` and `Date` implement `deconstruct_keys`, so `case t in {year: 2024, month: 2..3, hour:}` matches and binds.

## Compared with Python

The twin pins `TZ` the same way and uses `time.tzset()`, then builds `datetime(2024, 2, 29, 12, tzinfo=timezone.utc)`. Arithmetic goes through `timedelta` in both directions: `+ timedelta(days=1)` and `later - t` is `1 day, 0:00:00` (rows 2–3), with `total_seconds()` for the Float Ruby gives directly. `strftime` is the C library's, so `%-d` and `%e` are not portable (row 5); `isoformat()` writes `+00:00` where Ruby writes `Z` (row 6); `timestamp()` is a float (row 7). The big structural difference is rows 8–11: Python does not flag UTC versus local but *aware* versus *naive* — `fromtimestamp(0)` and `datetime(2024, 2, 29, 12)` have `tzinfo None`, and a naive value is not equal to an aware one and cannot be ordered against it (`TypeError`, row 9) — where Ruby's `Time.new` result compared equal to `t`. A fixed offset is `timezone(timedelta(hours=2))` (row 10), and `astimezone` is `getlocal` (row 11). Python raises for February 30th *and* for hour 25 (row 13) where Ruby rolled the day over. `fromisoformat` and `strptime` need no import (row 15), and `Z` is accepted since 3.11 (row 17). `date` has no month step: row 18's `add_months` uses `calendar.monthrange` for the clamp, and `date - date` is a `timedelta` (row 19). `calendar.isleap` is `Date.leap?`, `date(2024, 2, 30)` is a `ValueError` (row 21), `weekday()` counts from Monday=0 where `wday` counts from Sunday=0 (row 22), and there is no negative day — `monthrange(y, m)[1]` is the last day (row 23). One `datetime` class does both jobs (row 26), and pattern matching reads attributes through a class pattern rather than `deconstruct_keys` (row 27). Ruby's `Rational` for `Date - Date` connects to [Rational and BigDecimal](../../15_Numbers/rational_and_bigdecimal/README.md); the seconds Float to [Floats and rounding](../../15_Numbers/floats_and_rounding/README.md).

```ruby
# Kata: for a few fixed dates, the next leap day and how many days away it is,
# with Date arithmetic only -- Date.leap?, Date.new and Date - Date.
require "date"

def next_leap_day(from)
  year = from.year
  year += 1 until Date.leap?(year) && Date.new(year, 2, 29) > from
  Date.new(year, 2, 29)
end

[Date.new(2024, 1, 1), Date.new(2024, 2, 29), Date.new(2099, 6, 15), Date.new(2100, 1, 1)].each do |from|
  leap = next_leap_day(from)
  puts format("%s -> %s in %4d days (%s)", from, leap, (leap - from).to_i, Date::DAYNAMES[leap.wday])
end
```
