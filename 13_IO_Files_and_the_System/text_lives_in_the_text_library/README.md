# Text lives in the Ruby text library

**Level:** 101 · a map for anyone who came to this library looking for strings, encodings, regex or literals

**One line:** a Ruby `String` is bytes plus an encoding label — one type, where Python has `str` and `bytes` — and everything that follows from that is measured in the [Ruby text library ↗](https://masiarek.github.io/ruby-text-learning-library/), lesson by lesson, so this library links there instead of repeating it; the table below puts each of its twenty-three lessons beside the Python library page on the same idea.

The one measured thing on this page is the label. `"café"` under `-E UTF-8` is a `String` whose `encoding` is `UTF-8`, whose `length` is 4 characters and whose `bytesize` is 5 bytes. `force_encoding` changes the label and leaves the bytes; `encode` changes the bytes to say the same text under another label; `.b` is a copy labelled `BINARY` (`ASCII-8BIT`); an invalid byte is allowed in and only fails when something needs to read it as characters; two Strings with different non-ASCII encodings cannot be concatenated; and a character that US-ASCII cannot write is an `Encoding::UndefinedConversionError` unless you say what to replace it with. Characters, bytes and code points are three different counts, `\w` matches ASCII only while `\p{L}` matches letters, padding counts characters, and slicing a String by index gives characters while `byteslice` gives bytes. Every one of those rows is a page in the text library, where it is measured properly.

## Reading the output

Rows 1–4 are the four numbers a String carries: one label (`UTF-8`), 4 characters, 5 bytes (`é` is `0xC3 0xA9`), 4 code points, valid, and not ASCII-only. Row 5: `.b` is the same five bytes under the `BINARY` label, so its `length` is 5 and it is *not* `==` to the original — equality compares bytes *and* compatible labels. Row 6 is the difference between relabelling and converting: `force_encoding("ISO-8859-1")` makes the same bytes read as five characters, `encode("ISO-8859-1")` makes four bytes with `é` as `233`. Row 7: a lone `"\xE9"` is a String that is not valid UTF-8 — it exists, and `valid_encoding?` says so — and once relabelled as Latin-1 it converts to a proper `é`. Row 8: US-ASCII cannot hold `é`, so `encode` raises `Encoding::UndefinedConversionError` with the code point in its message, `undef: :replace` writes `?`, and `fallback:` lets you choose `e`. Row 9: `Encoding::CompatibilityError` when both sides have non-ASCII bytes under different labels. Row 10: the three defaults — external (set to UTF-8 by this library's runner), the source file's own, and the empty String's — and `String.new`, which is `BINARY`. Row 11: `e` plus a combining acute is 2 code points but 1 grapheme cluster, NFC normalization folds it into the precomposed `é`, and `upcase` is full Unicode — `ß` becomes `SS`. Row 12: `\w` stops before `é`, `\p{L}` matches the whole word. Row 13: `%-6s` pads to six *characters*. Row 14: `s[3]` and `s[-1]` are the character `é`, `byteslice(3, 2)` is its two bytes, and `byteslice(3, 1)` is half a character, which is not valid.

## Compared with Python

Python has two types where Ruby has one type and a label. A `str` is text and carries no encoding at all (row 1 prints `n/a` where Ruby printed `UTF-8`); `bytes` is the other type, and `s.encode()` crosses from one to the other (row 5: a `bytes` of length 5, never `==` to the `str`). There is therefore nothing to relabel (row 6), no `valid_encoding?` because a `str` cannot be invalid (row 4), and the failures move to the boundary: `b"\xe9".decode()` raises `UnicodeDecodeError` at once (row 7) where Ruby let the byte in and reported it later, `encode("ascii")` raises `UnicodeEncodeError` with `errors="replace"` and `"xmlcharrefreplace"` as the escape hatches (row 8), and `str + bytes` is a `TypeError` whatever the bytes hold (row 9), where Ruby raised only because both sides had non-ASCII characters. Rows 11–14 agree on the counts and disagree on two defaults: the standard library has no grapheme clusters, and `\w` matches `é` because Python's regex is Unicode by default — the opposite of Ruby's ASCII `\w`. The Python library's [`str` is not `bytes` ↗](https://masiarek.github.io/python-learning-library/01_Text_and_Bytes/str_is_not_bytes/index.html) and [Encode and decode ↗](https://masiarek.github.io/python-learning-library/01_Text_and_Bytes/encode_and_decode/index.html) are the two pages behind this section, and the table above pairs the rest.

```ruby
# Kata: describe(name, str) -- encoding label, characters, bytes, validity --
# for strings that share bytes or characters but not labels.
def describe(name, str)
  puts format("%-11s %-10s chars=%d bytes=%d valid=%-5s ascii_only=%s", name, str.encoding, str.length, str.bytesize, str.valid_encoding?, str.ascii_only?)
end

utf8 = "caf\u{e9}"
describe "utf8", utf8
describe "utf8.b", utf8.b
describe "latin1", utf8.encode("ISO-8859-1")
describe "relabelled", utf8.dup.force_encoding("ISO-8859-1")
describe "invalid", "caf\xE9"
describe "ascii", "cafe"
```
