# `unless` negates `if`; modifiers hang off the end of a line

**Level:** 101 · a Python programmer meeting `unless`, `until` and `x if c` for the first time

**One line:** Ruby spells `if not` as `unless` and `while not` as `until`, lets any statement carry `if`, `unless`, `while` or `until` at its end, and gives a do-while with `begin … end while`; Python has none of those spellings and no do-while, but has the `for … else` that Ruby lacks.

`unless c` runs its body when `c` is false and may take an `else`, but not an `elsif`. `until c` loops while `c` is false. Both, and `if` and `while`, can follow a statement as a *modifier* — `retry if attempts < 3`, `queue.shift until queue.empty?` — and a modifier tests its condition before the first run, exactly like the block form. The one exception is `begin … end while c`: a `begin` block with a `while` or `until` modifier runs its body once before testing, which is Ruby's do-while. `loop do … end` runs until `break`, and `break`'s argument becomes the loop's value. The spelling of else-if is `elsif`, and the program measures what happens when a Python programmer types `elif` or `else if` instead: a syntax claim is measured by compiling a string and printing the exception class, so nothing here is asserted from memory.

## Reading the output

Row 1: with `1 > 2` false, `unless` ran its body, so `x` is `"body"`. Row 2: `unless … elsif` does not compile — Ruby's grammar gives `unless` an `else` and nothing more, since "unless this, else if that" reads badly. Row 3: `until n >= 4` counted `n` up to `4`. Row 4: the trailing forms `r << "if" if true` and `r << "unless" unless false` both ran.

Rows 5 and 6 are the pair to remember. `n += 1 while n < 3` with `n` at 10 leaves `n` at `10`: a modifier `while` tests first and the body never ran. `begin n += 1 end while n < 3` leaves `n` at `11`: with a `begin … end` block in front, the body runs once before the test. That is the do-while, and it is the only case in which a modifier does not test first.

Row 7: `loop do … end` is a method with a block, not a keyword; `break i * 10` ended it and made `30` the value of the whole `loop` call. Row 8: `elsif` compiles. Row 9: `elif true` also compiles — not because Ruby knows `elif`, but because it parses as a call to a method named `elif` with the argument `true`; the mistake surfaces only when that branch runs, as a `NoMethodError`. Row 10: `else if` opens a second, nested `if` that needs its own `end`, so with one `end` it is a `SyntaxError` and with two it compiles — as two nested conditionals, not as an else-if. Row 11: `y = 5 if false` never assigns, but the parser has seen `y = …`, so `y` exists and is `nil` — `defined?(y)` says `"local-variable"`. Row 12: `for … else` does not compile; the search-with-a-miss idiom is `find`, which returns the hit or `nil`.

## Compared with Python

Python negates with `not` and has no second spelling: `unless` and `until` are syntax errors (rows 1 and 3), and `if not c:` keeps its `elif` where Ruby's `unless` refuses `elsif` (row 2). Nothing can trail a statement (rows 4 and 5): Python's `x if c else y` is an expression, must have its `else`, and cannot stand in for a statement modifier. There is no do-while (row 6) — the idiom is `while True:` with a `break` at the bottom — and no `loop` keyword (row 7); `while True:` serves both. `elif` is the spelling (rows 8 and 9), and `else if` is an error while `else:` with a nested `if` compiles (row 10), just as in Ruby. Row 11 is the sharpest contrast: after `if False: y = 5`, the name `y` does not exist and reading it raises `NameError`, where Ruby's parser had already created the variable. Row 12 is the feature Python has and Ruby lacks: `for … else`, whose `else` runs only when the loop finished without `break` — so the twin prints `break at 9` for one list and `else ran` for the other.
