# `Object` sits on `Kernel` on `BasicObject`

**Level:** 301 · a Ruby programmer who wants to know where `puts` comes from and what a "blank slate" object really is

**One line:** `Object.ancestors` is `[Object, Kernel, BasicObject]` and `Object` itself defines no public methods — every method a plain object has is `Kernel`'s (including the private "functions" `puts`, `p`, `require`, `raise` and `lambda`) or `BasicObject`'s eight (`==`, `equal?`, `!`, `__send__`, `instance_eval` and three more) — so a subclass of `BasicObject` cannot `puts`, `raise`, `inspect` or even name `String` without `::`, which is exactly what makes it the right base for a proxy that forwards everything through `method_missing`.

There is no "global function" in Ruby. What looks like one — `puts "x"`, `require "json"`, `raise "boom"` — is a private instance method of the `Kernel` module, mixed into `Object`, called on whatever `self` happens to be. That is why a bare `puts` works inside any method of any class, why `5.method(:puts)` exists, and why the top-level `self` (`main`) can call them. `BasicObject` is the root above all that: a class with eight public methods and five private hooks, whose subclasses start with nothing — no `class`, no `inspect`, not even `Object`'s constants. The program measures the three layers, then builds one bare object and one forwarding proxy on `BasicObject`.

## Reading the output

- **1.** `BasicObject` has no superclass (`nil`); `Object`'s is `BasicObject`, with the module `Kernel` between them. `Object.instance_methods(false)` is empty: `Object` adds no public methods of its own. Its private list holds `:row` and `:section` — the two helpers this very program defined with a top-level `def`. A top-level `def` defines a *private instance method of `Object`*, which is why every object, and every class body, can call such a helper without a receiver.
- **2.** The whole of `BasicObject`: eight public methods — `!`, `!=`, `==`, `__id__`, `__send__`, `equal?`, `instance_eval`, `instance_exec` — and five private ones, all hooks: `initialize`, `method_missing` and the three `singleton_method_*` callbacks.
- **3.** The "functions" are private instance methods of `Kernel`; the everyday methods — `inspect`, `to_s`, `respond_to?`, `is_a?`, `class`, `nil?`, `send`, `freeze`, `dup` — are its public ones. `method(:puts).owner` is `Kernel`, and so is `5.method(:puts).owner`: an Integer has `puts`, privately. `Kernel.singleton_methods` also includes `puts`, because these are module functions — callable as `Kernel.puts` with an explicit receiver, which row 4 uses. At the top level `self` is `main`, an instance of `Object`.
- **4.** Inside `Bare < BasicObject`, `puts` and `raise` are `NoMethodError`s and `String` is `NameError: uninitialized constant Bare::String` — constant lookup walks the ancestors, and `Object`, where the core constants live, is not one of them. The escape hatch is a leading `::`: `::Kernel.puts` and `::String` work. From outside, `bare.inspect`, `bare.class` and `p bare` all fail (`p` calls `inspect`). What does work is what `BasicObject` owns: `==` (identity, so a second `Bare.new` is not equal), `equal?`, `!` and `instance_eval`. `Object === bare` is `false`: a bare object is not an `Object`.
- **5.** A proxy on `BasicObject` with a `method_missing` forwards everything, because almost nothing is defined: `sort`, `size`, `inspect`, `respond_to?` — and `class`, so `pr.class` answers `Array`. On an `Object`-based proxy those four would be answered by `Kernel` and never reach `method_missing`. `Proxy.ancestors` is just `[Proxy, BasicObject]`. [`method_missing` and `respond_to_missing?`](../../10_Metaprogramming/method_missing_and_respond_to_missing/README.md) has the rest of the technique, and [building a DSL](../../10_Metaprogramming/building_a_dsl/README.md) is where it is used.

## Compared with Python

Python's root is `object`, and the differences start there. Row 1–2: `object` is not small — `dir(object)` lists 24 names, and they are its own (`vars(object)` holds them), where Ruby's `Object` owns nothing and borrows from `Kernel`. Row 3: `builtins` is Python's `Kernel`, but it is a *module* every scope sees, not a mixin every object carries — `print is builtins.print` and `print.__module__` is `builtins`, while `hasattr(5, 'print')` is `False`, where Ruby's `5.method(:puts)` exists. Row 4 is the structural difference: there is no class below `object`. Every class has it as a base, `del object.__repr__` is a `TypeError` (the type is immutable), and setting a class's `__bases__` to `()` is a `TypeError`, so no Python class can be a blank slate: `Bare()` has `__repr__`, `__eq__`, `__hash__` and the rest whether it wants them or not. Row 5: a proxy uses `__getattr__`, which runs only when normal lookup fails, so `pr.copy()` is forwarded — but implicit special-method calls look on the *type*, not the instance, so `len(pr)` is a `TypeError` even though the explicit `pr.__len__()` is forwarded fine; and `pr.__class__` and `repr(pr)` stay the proxy's own, where Ruby's proxy forwarded `class` and `inspect`. `__getattribute__` intercepts every lookup, hit or miss, which is closer to `method_missing`'s reach, and then has to fetch its own state through `object.__getattribute__`.

```ruby
# Exercise 1: a Recorder proxy on BasicObject. It forwards every call to the
# target and keeps the names, and because BasicObject has no `class`, `nil?`
# or `inspect`, those calls are recorded and forwarded too.

class Recorder < BasicObject
  def initialize(target)
    @target = target
    @calls = []
  end

  def __calls = @calls

  def method_missing(name, *args, &blk)
    @calls << name
    @target.__send__(name, *args, &blk)
  end
end

rec = Recorder.new(%w[pear apple fig])

puts "rec.size            #{rec.size}"
puts "rec.first           #{rec.first}"
puts "rec.sort            #{rec.sort.inspect}"
puts "rec.class           #{rec.class}"
puts "rec.nil?            #{rec.nil?}"
puts "rec.inspect         #{rec.inspect}"
puts "rec.map(&:upcase)   #{rec.map(&:upcase).inspect}"
puts "recorded            #{rec.__calls.inspect}"
puts "rec.equal?(rec)     #{rec.equal?(rec)}   (equal? is BasicObject's own, so it was not recorded)"
```
