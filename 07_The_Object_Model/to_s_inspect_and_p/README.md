# `puts` calls `to_s`, `p` calls `inspect`

**Level:** 201 · anyone who has seen `#<Foo:0x000...>` and wanted a better line

**One line:** Every object answers two questions — `to_s`, "show this to a person", and `inspect`, "show this to a programmer" — and every printing route picks one: `puts`, interpolation, `%s` and `String()` use `to_s`, while `p`, `%p`, `pp` and every container's `to_s` use `inspect`; defining one never defines the other, `p` returns what it printed and `puts` returns `nil`, and `puts nil` writes an empty line.

The default `to_s` is `#<Plain:0x…>` with the object's address; the default `inspect` is the same plus the instance variables, which is the line you see from `p`. Since the address changes from run to run, the program tests the shape of those defaults instead of printing them, and prints the real strings only for classes that define their own. Both methods live in `Kernel`, so `BasicObject` has neither — a [proxy built on `BasicObject`](../basic_object_and_kernel/README.md) cannot even be `p`'d.

## Reading the output

- **1.** A bare class gets a `to_s` of `#<Plain:0x…>`, and its `inspect` is the same string; give the object instance variables and only `inspect` grows to list them (`@x=1, @y=2`), while `to_s` stays as it was.
- **2.** Defining `to_s` leaves `inspect` at the default and defining `inspect` leaves `to_s` at the default. There is no fall-back in either direction: a class that wants both must write both.
- **3.** `puts`, `"#{}"`, `%s` and `String()` all end up in `to_s`; `p` and `%p` end up in `inspect`.
- **4.** A container's `to_s` *is* its `inspect`, and it inspects its elements — `[obj].to_s` shows `#<Both 3>`, not `to_s of 3` — so interpolating an array into a string gives the programmer's view of each element. `puts [obj]` is the exception: `puts` flattens an array and calls `to_s` on each element separately.
- **5.** `p obj` prints and then returns `obj` itself, which is why `p` can be dropped into the middle of an expression to look at a value; `p 1, 2` prints two lines and returns the array `[1, 2]`; `p` with nothing returns `nil`; `puts` always returns `nil`.
- **6.** `puts nil` writes a bare newline, `p nil` writes `nil`, and `print nil` writes nothing — because `nil.to_s` is `""` and `nil.inspect` is `"nil"`. The same applies inside interpolation: `"#{nil}"` is the empty string.
- **7.** A string's `to_s` is itself; its `inspect` adds the quotes and escapes a tab as `\t` — but leaves `é` as is, since the program runs under `-E UTF-8`. A symbol's `inspect` keeps the colon and its `to_s` drops it.
- **8.** `Struct`, `Data`, exceptions, floats and ranges all define both: a Struct's `to_s` is its `inspect`, an exception's `to_s` is its message and its `inspect` wraps the class around it, and `1e20.to_s` is `1.0e+20`.
- **9.** `PP.pp(object, $stdout, 40)` is `pp` with an explicit width: it breaks the nested hash across lines and indents each level. Plain `pp` picks its width from the terminal, so the program pins it. *(Not machine-checked here.)* For an object whose `inspect` is short, `pretty_inspect` is just `inspect` plus a newline.
- **10.** `to_s` and `inspect` are owned by `Kernel`, not `Object`; `p` is a private instance method of `Kernel` — a method every object has and calls without a receiver; and `BasicObject` has no `inspect` at all.

## Compared with Python

Python's two questions are `__str__` and `__repr__`, and the same routes lead to them: `print`, `f"{x}"`, `%s` and `str()` call `__str__`; `repr()`, `f"{x!r}"`, `%r` and every container call `__repr__`. Four rows differ. Row 1: Python's default `__repr__` is `<__main__.Point object at 0x…>` with no attributes — where Ruby's default `inspect` lists the instance variables, Python makes you ask `vars()`. Row 2: defining `__repr__` alone *does* give you `str()`, because `object.__str__` falls back to `__repr__`; Ruby's `to_s` never falls back to `inspect`. Row 4: `print([obj])` prints the list's `repr`, elements included — the same as Ruby's `[obj].to_s` — but Ruby's `puts [obj]` flattens the array and prints each element's `to_s`, which Python's `print` never does. Row 6: `print(None)` writes `None`, where `puts nil` writes an empty line. Python has no `p`: `print` always returns `None`, so the program defines a four-line `p` helper that prints the `repr` and returns its argument. It also has no Symbol; an `Enum` member is the nearest thing, with a `str` of `Sym.sym` and a `repr` of `<Sym.sym: 1>`. Dataclasses and namedtuples write a `__repr__` for you the way `Struct` and `Data` write an `inspect`, `pprint.pprint(width=40)` is `PP.pp` with a width, and `pformat` of a short object is its `repr`. The Python library's [`repr` is not `str` ↗](https://masiarek.github.io/python-learning-library/01_Text_and_Bytes/repr_is_not_str/index.html) goes further into what `repr` escapes and why `str.isprintable` is defined in terms of it.

## Try it

1. Write a `Version` class built from `"1.2.3"` whose `to_s` is the dotted string and whose `inspect` is `#<Version 1.2.3>`. Print one with `puts`, `p`, interpolation, inside an array, and through `format("%s / %p")`; use `p`'s return value in an expression; then include `Comparable` with a `<=>` on the numeric parts and sort `["1.10.0", "1.2.3", "1.2.10"]` correctly.
2. Write a module `Inspectable` whose `inspect` lists the class name and every instance variable (`instance_variables` and `instance_variable_get`) without an address, and include it in two different classes. Check that `p` and `[obj].to_s` both use it and that `puts obj` still does not.

```ruby
# Exercise 1: a Version with a to_s for people and an inspect for programmers.
# Print it every way a value gets printed, and show that p hands it back.

class Version
  include Comparable
  attr_reader :parts

  def initialize(text) = @parts = text.split(".").map(&:to_i)
  def <=>(other) = parts <=> other.parts
  def to_s = parts.join(".")
  def inspect = "#<Version #{self}>"
end

v = Version.new("1.2.3")

print "puts v          -> "
puts v
print "p v             -> "
p v
puts "\"\#{v}\"          -> #{v}"
puts "[v].to_s        -> #{[v]}"
puts "format %s / %p  -> #{format('%s / %p', v, v)}"
puts "p returns it    -> #{p(v).to_s}"
puts "sorted          -> #{[Version.new('1.10.0'), v, Version.new('1.2.10')].sort.inspect}"
```
