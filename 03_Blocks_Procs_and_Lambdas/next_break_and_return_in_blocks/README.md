# `next`, `break` and `return` leave a block differently

**Level:** 201 · anyone who reached for `continue` inside a Ruby block

**One line:** `next v` ends this run of the block with `v` as its value, `break v` ends the method the block was given to and makes `v` that call's value, and `return` ends the method the block was written in — three exits at three distances — while `redo` runs the same iteration again.

A block has three ways out, each reaching a different distance. `next v` ends the current run of the block and makes `v` the value `yield` sees, so inside `map` it supplies that element's result; a bare `next` supplies `nil` (row 1). `break v` ends the method the block was given to — `each`, `map`, `loop` — and makes `v` the value of that whole call, whatever the method would otherwise have returned: `each` returns its receiver when no `break` runs (row 2), `map` returns 200 instead of an array (row 3), and an endless `each` or a `loop` returns the value handed to `break` (row 4). `return` reaches furthest: it ends the method the block was *written in*, however many blocks deep (row 5). `redo` restarts the current iteration without advancing (row 6). Procs and lambdas obey the same words with the block's rules: `next` ends either kind with a value (row 7); `break` in a lambda acts like `return`, `break` in a proc called with `call` has no method call to end and raises `LocalJumpError`, but the same block reached through `yield` or an `&b` parameter ends the method it was given to (row 8). `ensure` runs on every exit (row 9), and `while` — a statement in Python — breaks with a value too (row 10).

## Reading the output

Row 1 is `[1, 0, 3]`: the even element's run ended early with 0, and `[nil]` is what a bare `next` leaves. Row 2 prints 42 — `each` never got to 3 — and then `[1, 2, 3]`, the receiver, which is what `each` returns when the block runs to the end every time. Row 3 prints 200 where an array would be, and `nil` for a bare `break`. Row 4 stops an endless range at 8, the first square above 50, and `loop { break :done }` evaluates to `:done`. Row 5 prints 4, the first even number; `:none`, the value after the loop when nothing matched; and `[1, 20]` from a `return` two blocks deep. Row 6 counts three runs of the block for two elements, `seen [1, 1, 2]`, because the first run asked for a `redo`. Row 7 gets 6 from both a proc and a lambda whose `next x * 2` made `:unreached` unreachable. Row 8 is the one to read slowly: `break` in a lambda gave 5 like a `return`; `break` in a proc invoked by `call` raised `LocalJumpError: break from proc-closure`; the same `break` in a block reached by `yield` gave 8 and by `b.call` inside the method it was given to gave 9. Row 9 prints `ensure ran` before the value `:out` reaches the caller, and row 10 prints the 3 that `while … break 3` evaluated to.

## Compared with Python

Python's `continue`, `break` and `return` are statements with no value and no place inside an expression, which reshapes every row. Skipping is `continue`, and a value for the skipped element has to come from a conditional expression in a comprehension (row 1); `break` ends the loop and any result is left in a variable, because `x = for …` does not parse (row 2); `break` cannot appear inside a comprehension at all, so the early exit is a generator expression consumed by `next` (row 3); an endless `itertools.count` loop leaves its answer in `i` (row 4). `return` is the one that matches Ruby exactly, leaving the function from any depth of loop (row 5). There is no `redo` — a `while` loop that declines to advance its index does the same job (row 6). `return` inside a generator ends the generator, and the value rides on `StopIteration.value` (row 7). A `break` outside a loop is refused when the code is compiled, even inside a lambda or a function body (row 8): the compile-time version of Ruby's run-time `LocalJumpError`. `finally` runs on the way out just as `ensure` does (row 9), and `for … else` is Python's own addition: the `else` suite runs only when the loop ended without a `break` (row 10). The statements are documented under [`break` and `continue` ↗](https://docs.python.org/3/reference/simple_stmts.html#the-break-statement), [the `for` statement and its `else` ↗](https://docs.python.org/3/reference/compound_stmts.html#the-for-statement) and [`StopIteration` ↗](https://docs.python.org/3/library/exceptions.html#StopIteration).

## Try it

1. Write `first_over(limit, xs)` three ways — with `find`, with `each` and `break`, and with `each` and `return` — and print what each returns when nothing matches. The `break` version returns the whole array in that case, because a `break` that never runs leaves `each` to return its receiver; fix it with an explicit value after the loop.

Do it once with `return`, then try `break` alone — it leaves one level, so the outer loop keeps going — then with `catch` and `throw` from [`throw` and `catch`](../../08_Errors_and_Exceptions/throw_and_catch/README.md), and finally with `xs.combination(2).find`.

```ruby
# Exercise 1: first_over(limit, xs) three ways -- find, each + break, and
# each + return -- and what each returns when nothing matches.

def with_find(limit, xs)
  xs.find { |x| x > limit }
end

def with_break(limit, xs)
  xs.each { |x| break x if x > limit }      # no match: each returns xs itself
end

def with_break_fixed(limit, xs)
  xs.each { |x| break x if x > limit }
  nil                                       # each's value is dropped; nil is explicit
end

def with_return(limit, xs)
  xs.each { |x| return x if x > limit }
  nil
end

xs = [3, 8, 12]
puts "match at 5:    find #{with_find(5, xs)}, break #{with_break(5, xs)}, return #{with_return(5, xs)}"
puts "no match at 20: find #{with_find(20, xs).inspect}, break #{with_break(20, xs).inspect} (the trap), fixed #{with_break_fixed(20, xs).inspect}, return #{with_return(20, xs).inspect}"
puts "all three agree on a match: #{[with_find(5, xs), with_break(5, xs), with_return(5, xs)].uniq.size == 1}"
```
