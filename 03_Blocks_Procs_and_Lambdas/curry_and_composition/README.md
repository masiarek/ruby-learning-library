# Procs curry and compose

**Level:** 201 · anyone who has used `functools.partial` and wants Ruby's equivalent — and the two things Python lacks

**One line:** `Proc#curry` turns an n-argument lambda into a chain of one-argument lambdas, `>>` and `<<` compose any two callables into a new lambda, and `parameters` and `arity` describe what a proc or method expects; Python has `functools.partial` and `inspect.signature`, but no curry and no composition operator.

`curry` rewrites a lambda so that it can be fed its arguments one call at a time: `add.curry[1][2]` is 3, and so are `.(1).(2)` and `[1, 2]` given at once (row 1). Each partial step is a real lambda, so `add.curry[1]` can be kept as `inc` and used later (row 2), and a three-argument lambda accepts its arguments in any grouping (row 3). Currying a proc keeps the proc's rules — the result is still not a lambda — and a curried lambda reports `arity` -1, because each step accepts any number of arguments (row 4). A variadic lambda has no fixed count to wait for, so `vsum.curry[1]` simply calls it, and `curry(3)` tells it how many to collect; on a fixed-arity lambda the same `curry(3)` is an `ArgumentError` (row 5). Composition is two operators: `f >> g` is a lambda that runs `f` and then `g`, `f << g` runs `g` first (row 6). Both return a `Proc` that is a lambda, and both accept anything that answers `call` — a `Method`, a `Proc`, a `Symbol#to_proc` — so a chain of three composes and the result can be passed with `&` (row 7); a list of steps folds into a pipeline with `reduce(:>>)`, and the difference between the two operators shows in `sq << double` against `sq >> double` (row 8). The right-hand side of `>>` may be any object with `call`, but the left-hand side must be a `Proc` or a `Method`, because `>>` is a method of those two classes (row 9). `parameters` and `arity` describe the shape of any of them — required, optional, rest, required keyword, keyword, keyword rest and block, with `arity` negative once the count is open — and `Method#curry` curries a method the same way (row 10).

## Compared with Python

Python's `functools.partial` is the nearest thing to `curry`, and it is a different thing: it applies some arguments now and returns a callable that takes the rest in one call, so `partial(add, 1)(2)` is 3 but nothing chains by itself — currying by hand is a lambda returning a lambda (row 1). A `partial` remembers its `func`, `args` and `keywords` (row 2), nests to split three arguments any way (row 3), can fix a keyword argument, and checks nothing early: `inspect.signature(inc)` shows the one parameter left (row 4), too many arguments fail only when the partial is called, and a variadic accepts any split (row 5). There is no composition operator — `f >> g` on two functions is a `TypeError` — and the idiom is a two-line `compose` returning a lambda (row 6); it returns a `function`, takes any callables including `str` and `len` (row 7), folds into a pipeline with `functools.reduce`, and shows the same order sensitivity (row 8). Because `compose` is a plain function rather than a method of `Proc`, an object with `__call__` can stand on either side (row 9). `inspect.signature` is `parameters` and `arity` in one object: the printed signature, the parameter count, and each parameter's `kind` (row 10). The pieces are documented under [`functools.partial` ↗](https://docs.python.org/3/library/functools.html#functools.partial), [`functools.reduce` ↗](https://docs.python.org/3/library/functools.html#functools.reduce) and [`inspect.signature` ↗](https://docs.python.org/3/library/inspect.html#inspect.signature).

```ruby
# Exercise 1: pipeline(*callables) composes with reduce(:>>); a slug maker
# is built from three steps, and a three-argument clamp is curried down to
# a one-argument percentage clamp.

def pipeline(*steps) = steps.reduce(:>>)

slug = pipeline(:strip.to_proc, :downcase.to_proc, ->(s) { s.gsub(/\s+/, "-") })
puts slug.call("  Hello Big World ")
puts ["  A B ", "c"].map(&slug).inspect

clamp = ->(lo, hi, x) { x.clamp(lo, hi) }
to_percent = clamp.curry[0][100]
puts [-5, 42, 250].map(&to_percent).inspect
puts "to_percent.arity = #{to_percent.arity}, lambda? #{to_percent.lambda?}"

# the same clamp, fully applied in one go, and then composed after slug's length
puts clamp.curry[0, 100, 7]
puts (slug >> :size.to_proc >> to_percent).call("  a very long title indeed ")
```
