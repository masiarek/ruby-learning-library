# `7 / 2` is `3`: integer division floors

**Level:** 101 · a Python programmer's first week in Ruby

**One line:** Ruby's `/` on two Integers is Python's `//` — it floors and stays an Integer — so `7 / 2` is `3` and `-7 / 2` is `-4`; a Float answer needs `fdiv` or a Float operand, and only an Integer divided by zero raises.

Ruby has one division operator and lets the operands pick its meaning: two Integers give the floored Integer quotient, and a Float on either side gives a Float. Python 3 split the two meanings into two operators — `/` always answers in float and `//` floors — so a Python programmer who types `total / count` in Ruby gets a floored count where they expected an average. The rest of the family follows the same rule in both languages: `%` and `divmod` floor and take the divisor's sign, `remainder` truncates and takes the dividend's sign like C, and `div` floors to an Integer even from a Float. Where the two languages part is zero: a Float divided by zero is `Infinity` or `NaN` in Ruby, while in Python every division by zero raises.

## Reading the output

Rows 1–4 are the operator choosing its meaning from its operands. `7 / 2` is `3`, and `-7 / 2` is `-4`, not `-3`: the quotient is floored towards minus infinity, which is what Python's `//` does and what C's `/` does not. To get `3.5` you either call `fdiv` (row 3) or put a Float on one side (row 4); `quo` gives the exact answer, the Rational `(7/2)`.

Rows 5–9 are the remainders. `divmod` returns quotient and modulo as a pair, and `-7.divmod(2)` is `[-4, 1]` because `-4 * 2 + 1` is `-7`. `%` takes the sign of its divisor (rows 7 and 8), so `-7 % 2` is `1` and `7 % -2` is `-1`; `remainder` takes the sign of the dividend (row 9), which is what `%` does in C and Java, and it pairs with the truncated quotient rather than the floored one — the kata below checks both identities. Rows 10 and 11 are the two named divisions: `div` floors and always returns an Integer, even from a Float receiver, and `ceildiv` rounds the quotient up.

Rows 12–16 are zero. A Float divided by zero follows IEEE 754 — `Infinity`, or `NaN` for `0.0 / 0` — and nothing raises. An Integer divided by zero raises `ZeroDivisionError` (row 14), and so does `%` by zero even with a Float receiver (row 15). Row 16 is the trap on the way back: `to_i` on `Infinity` or `NaN` raises `FloatDomainError`, so a Float that went through a zero cannot quietly become an Integer.

## Compared with Python

Python 3 gave the two meanings two operators: `/` always answers in float, even for `4 / 2`, and `//` floors. So Ruby's `7 / 2` is Python's `7 // 2`, and Ruby's `7.fdiv(2)` is Python's plain `7 / 2`. From row 5 on the two languages agree on the floored family — `divmod`, and `%` with the divisor's sign — and Python's truncating counterpart to `remainder` is `math.fmod`, which answers in float. `//` on a float floors but keeps the float type (`7.0 // 2` is `3.0`), where Ruby's `div` returns an Integer. The real divergence is zero: Python raises `ZeroDivisionError` for every division by zero, float or int, and infinity and NaN exist only as `math.inf` and `math.nan`, never as the result of an arithmetic operator. The twin prints the exception's type only, because CPython reworded these messages between 3.12 and 3.14 — `integer division or modulo by zero` became `division by zero`. *(Not machine-checked here.)*

```ruby
# Kata: for every (a, b) in [7, -7] x [2, -2], print the floored pair
# (/ and %) and the truncated pair (fdiv.truncate and remainder), and check
# the identity each pair satisfies: a == q * b + r.

puts format("%-3s %-3s | %-6s %-6s | %-6s %-9s | %s",
            "a", "b", "a / b", "a % b", "trunc", "remainder", "both identities hold?")
[7, -7].product([2, -2]).each do |a, b|
  floored   = a / b
  modulo    = a % b
  truncated = a.fdiv(b).truncate
  remainder = a.remainder(b)
  floor_ok  = (a == floored * b + modulo)
  trunc_ok  = (a == truncated * b + remainder)
  puts format("%-3d %-3d | %-6d %-6d | %-6d %-9d | %s",
              a, b, floored, modulo, truncated, remainder, floor_ok && trunc_ok)
end
```
