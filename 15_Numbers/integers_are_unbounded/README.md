# Integers never overflow: `2 ** 200` is just an Integer

**Level:** 101 · a Python programmer's first week in Ruby

**One line:** Ruby has one `Integer` class with no ceiling — `2 ** 200` is an ordinary value with `bit_length`, `digits`, `to_s(2)`, `Integer.sqrt`, a modular `pow` and `gcd` — and the only way a big Integer loses digits is by passing through a Float; Python's `int` is the same, except that `str()` of a 5000-digit number raises unless you lift a limit.

Ruby integers are arbitrary precision, and there is no visible seam between a small one and a large one: both are the one class `Integer`, `2 ** 200` prints all 61 of its digits, and there is no overflow to check for. The two classes that used to expose the seam, `Fixnum` and `Bignum`, were folded into `Integer` in Ruby 2.4 *(Not machine-checked here.)*, and row 3 shows that the old names are `NameError`s today. What the class gives you is a toolbox built for numbers of any size: `bit_length`, `digits`, `to_s(base)`, `Integer.sqrt` (exact, where `Math.sqrt` rounds to a Float), `pow(b, m)` for modular exponentiation without the huge intermediate, `gcd` and `lcm`. The one boundary that matters is the Float: a double carries 53 bits of integer, so `(2 ** 53 + 1).to_f` silently becomes `2 ** 53`.

## Reading the output

Rows 1–3 are the one class. `2 ** 200` is a 61-digit Integer and its class is `Integer`, the same class `1` has; `Fixnum` is an uninitialized constant. Rows 4–7 are the bit and digit views. `bit_length` counts the bits needed to represent the number without its sign, so `255` needs 8 and `256` needs 9; for a negative number Ruby counts the bits of the two's-complement form without the sign bit, which is why `(-1).bit_length` is `0` and `(-256).bit_length` is `8`. `digits` returns the digits least-significant first — `digits[i]` is the coefficient of `base ** i` — in any base; `to_s(base)` writes the number out in bases 2 to 36 with no prefix and a leading minus for a negative.

Rows 8–11 are the arithmetic that stays exact. `Integer.sqrt(10 ** 40)` is exactly `10 ** 20`, where `Math.sqrt` answers `1.0e+20`, a Float that happens to be right here and will not be for a number whose root does not fit in 53 bits. `3.pow(200, 1000)` reduces modulo 1000 as it multiplies and never builds the 96-digit power. `gcd`, `lcm` and `gcdlcm` are methods on the Integer. Row 11 is the surprise for a Python reader: a negative exponent gives a `Rational`, `(1/2)`, not `0.5` — Ruby keeps the exact answer.

Rows 12–15 are the edges. `(2 ** 53 + 1).to_f.to_i` comes back as `2 ** 53`: the `+ 1` did not survive the trip through a 53-bit significand. There is no limit on `to_s` — a 5001-digit decimal or a 4153-digit hexadecimal prints as readily as `1` — and the literal forms are `0b`, `0o` and `0x`, with underscores allowed as digit separators and a bare leading `0` meaning octal, so `017` is `15`.

## Compared with Python

Python's `int` is the same idea — unbounded, and one class since Python 3 dropped `long` — and most rows agree to the digit: `bit_length`, `bin` and `hex` with a prefix where `to_s(2)` has none, `math.isqrt` for the exact root, `pow(3, 200, 1000)` for modular exponentiation, `math.gcd` and `math.lcm` as functions rather than methods, and the same `2 ** 53` loss through a float. Three rows differ. `(-1).bit_length()` is `1` in Python, which counts the bits of the magnitude, where Ruby's `0` counts the two's-complement bits without the sign. `2 ** -1` is the float `0.5`, not a `Fraction`. And Python is the language with a limit: converting an `int` with more than 4300 digits to or from a decimal string raises `ValueError` — a guard added in 3.11 against quadratic-time conversions of untrusted input *(Not machine-checked here.)* — and `sys.set_int_max_str_digits(0)` lifts it, while hexadecimal was never limited. Ruby has no such limit, in any base. Finally, a leading zero alone is a `SyntaxError` in Python 3, where `0o17` is the only octal form, while Ruby still reads `017` as octal.

The Python library's [`bin()` is not the bits ↗](https://masiarek.github.io/python-learning-library/01_Text_and_Bytes/bin_is_not_the_bits/index.html) works through why `bin(-255)` prints a minus sign rather than a two's-complement pattern; Ruby's `(-255).to_s(2)` does the same, and it is `bit_length` — row 5 — that shows the two's-complement view.
