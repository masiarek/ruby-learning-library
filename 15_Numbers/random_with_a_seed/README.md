# `Random.new(42)` gives the same numbers every run

**Level:** 201 · anyone who needs a test, a simulation or a shuffle to be repeatable

**One line:** A seeded `Random` is a function of its seed — `Random.new(42).rand(100)` is `51` on every run and every machine — and `shuffle`, `sample`, `srand` and `Kernel#rand` all draw from one; only `SecureRandom` and `Random.new_seed` are unpredictable. Python's `random.Random(42)` is just as repeatable, but the same small seed gives a different stream, and a wide seed gives the identical one.

`Random.new(seed)` builds a Mersenne Twister generator, and every value it produces is determined by the seed and the calls made so far: `rand(100)` for an Integer below 100, `rand` for a Float in `[0, 1)`, `rand(1..6)` for an inclusive range, `bytes` for raw bytes. That makes seeded output safe to record as an answer key, which is what this page's output is. `Array#shuffle` and `Array#sample` take a generator as `random:`; without one they use the process-wide generator that `Kernel#rand` uses and that `srand(seed)` reseeds, so `srand(42)` followed by `rand(10)` is as repeatable as an explicit `Random`. Two things are unpredictable on purpose: `Random.new_seed`, which asks the operating system for entropy, and `SecureRandom`, which never takes a seed and is the right tool for tokens and passwords; the program prints only their shape. The old constant `Random::DEFAULT` was removed in Ruby 3.2 *(Not machine-checked here.)*, and row 12 shows it is a `NameError` today.

## Reading the output

Rows 1–4 are one seed, four kinds of value. `51` is the first `rand(100)` of seed 42, and starting over from `Random.new(42)` gives the same five Integers, the same three Floats and the same ten dice throws — the stream depends on the seed and on how much has been drawn, never on the clock. Rows 5 and 6 are the process-wide generator: `srand(42)` makes `Kernel#rand` repeatable in the same way, a second `srand(42)` restarts the stream, and `srand` returns the seed it replaced. Rows 7 and 8 pass a generator to `shuffle` and `sample`, and the results are as fixed as the seed.

Rows 9–12 are the edges. Two generators built from the same seed are `==` as long as they have drawn the same amount; `rand` accepts any Integer bound, `2 ** 70` included; `rand(0)` on a `Random` is an `ArgumentError` — an empty range — while `Kernel#rand(0)` is the one exception, returning a Float as if no argument had been given; and `Random::DEFAULT` is gone. Rows 13 and 14 are the sources you cannot seed: `Random.new_seed` is a fresh Integer from the OS on every call, and `SecureRandom.hex(8)` is sixteen hex characters whose value the page cannot print because it will never repeat. Row 15 is the cross-language surprise: seeded with `2 ** 70`, Ruby's first `rand(2 ** 32)` and first `rand` are `999817988` and `0.2327882718301838` — and the Python twin prints exactly the same two numbers.

## Compared with Python

`random.Random(42)` repeats its stream just as faithfully, but for seed 42 it is a different stream: rows 1–4 print different numbers. Row 15 shows that this is not a different algorithm: both languages run MT19937, and for a seed wider than 32 bits they load it identically and produce the identical stream — the same 32-bit word, the same 53-bit float. The difference is only in how a seed that fits in one 32-bit word is loaded — Ruby hands it to the generator's single-word initialiser and CPython always uses the array initialiser *(Not machine-checked here.)* — so `42` does not port between the two languages while `2 ** 70` does. Everything else maps: `randrange(100)` for `rand(100)`, `random()` for `rand`, `randint(1, 6)` (inclusive, like a Range) for `rand(1..6)`, `random.seed(42)` for `srand(42)` — except that `seed()` returns `None` rather than the previous seed — and `getrandbits(70)` for `rand(2 ** 70)`. `shuffle` is a method of the generator, shuffles in place and returns `None`, where Ruby's returns a new array and takes the generator as a keyword. `Random` objects have no `==`; compare `getstate()`. `randrange(0)` raises `ValueError`. There is no `random.DEFAULT` either: the module-level functions are bound methods of one hidden `Random` instance. And `os.urandom` and `secrets` are the unseedable sources, printed by shape only, as in Ruby.

```ruby
# Kata: roll two dice 1000 times with a seeded generator and tally the sums.
# Seeded, the tally is the same on every run, so an answer key can hold it.

r = Random.new(2024)
sums = Array.new(1000) { r.rand(1..6) + r.rand(1..6) }
tally = sums.tally.sort.to_h
tally.each { |sum, count| puts format("%2d %-4d %s", sum, count, "#" * (count / 5)) }
most = tally.max_by { |_, count| count }
puts "most common: #{most[0]} (#{most[1]} times); mean #{sums.sum.fdiv(sums.size)}"
```
