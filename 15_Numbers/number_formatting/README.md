# Numbers become text with `format`, `to_s(16)` and `%`

**Level:** 201 · anyone printing a price, a hex dump or a table

**One line:** `format` speaks C's mini-language — with `..`-prefixed two's-complement negatives and no thousands flag — `to_s(base)` and `to_i(base)` go between bases, `Integer()` parses strictly where `to_i` never fails, and `Float#to_s` prints the shortest string that reads back as the same Float; Python's f-strings add a `,` flag, keep the minus sign on a negative, and switch to exponent form one digit later.

`format(spec, *args)` — also `sprintf`, and `spec % args` on a String — is where Ruby turns a number into text with a width, a precision or a base: `%.2f`, `%08.3f`, `%e`, `%x`, `%b`, `%o`, `%+d`, `%-5d`, and `%#x` for a prefix. `Integer#to_s(base)` writes any base from 2 to 36 without a prefix, and `String#to_i(base)`, `hex` and `oct` read it back — never failing, so junk becomes `0` — while `Integer(str)` and `Float(str)` raise on anything that is not a number and read `0x`, `0b`, `0o` and a bare leading `0` as prefixes. A Float prints itself as the shortest decimal that reads back as the same Float — `0.30000000000000004`, `1.0e+20` — and formatting is how you choose the digits instead. Two rounding facts come with all this: `format("%.2f", 2.675)` is `"2.68"` where Python prints `2.67`, and `Integer#round(-2)` rounds a half away from zero, so `1250.round(-2)` is `1300`.

## Reading the output

Rows 1–7 are `format`. The directives are C's: a precision after the dot, a width before it, `0` to fill with zeros, `+` for an explicit sign, `-` to left-align, `e` and `g` for the scientific and the shorter form, `x`, `b` and `o` for bases, and `#` for a prefix — where Ruby's octal prefix is a bare `0`, not Python's `0o`. Row 6 is Ruby's own convention for a negative number in a base: `%08b` of `-5` is `..111011`, the two's-complement bit pattern with `..` standing for the infinite run of ones to its left, and `%x` of `-255` is `..f01`. Row 7 is a rounding surprise: the Float `2.675` is stored as a value just below 2.675, and rounding that exact value — what Python does — gives `2.67`, but Ruby's `format` gives `2.68`; `2.665` gives `2.66` and `2.685` gives `2.68`, which is the pattern of rounding the decimal digits `2.675` half to even, the shortest form rather than the exact value *(Not machine-checked here.)*. Row 8 is the missing feature: `format` has no thousands separator, so Ruby code inserts commas with a regex — `\B(?=(\d{3})+\z)` marks every position that is followed by a multiple of three digits — and `%,d` is a malformed format string.

Rows 9–12 are bases and parsing. `to_s(16)`, `to_s(2)` and `to_s(36)` write a number in any base; `hex`, `to_i(16)` and `to_i(0)` — base 0 reads the prefix — bring it back. The `to_i` family never raises: `"zz".hex` is `0`, and `"08".to_i` is `8`. `Integer()` is the strict parser: it understands prefixes and underscores, and it raises on junk — including `"08"`, because a leading `0` makes it read octal, where 8 is not a digit. Rows 13 and 14 are `Float#to_s`: the shortest round-trip form, always with a decimal point or an exponent, switching to `1.0e+15` form once the integer part reaches 16 digits and to `1.0e-05` form below `0.0001`. Rows 15 and 16 are rounding against formatting: `round(2)` and `floor(2)` return Floats, `round(-2)` returns an Integer and rounds a half away from zero (`1250` to `1300`), and `round` drops trailing zeros — `3.1.round(2)` prints as `3.1` — where `format("%.2f", 3.1)` keeps them, which is why money is formatted, not rounded.

## Compared with Python

The mini-language is the same one — `format(x, ".2f")`, `f"{x:08.3f}"`, `%` on a string — with a few additions and two different conventions. Python has a thousands flag built in, `f"{n:,}"` and `f"{n:_}"`, which is row 8's regex in one character. `hex`, `bin` and `oct` always carry their prefix (`format(255, "x")` is the bare form), and `#o` gives `0o377`. A negative number keeps its minus sign in every base — `f"{-5:08b}"` is `-0000101` — where Ruby shows two's complement. `int(s, base)` is strict like `Integer()`: junk raises, a prefix needs base 0 or the matching base, and `int("08")` is simply `8`, because a leading zero means nothing in base 10 (`int("017", 0)` raises instead). Row 7 is the rounding difference: `format(2.675, ".2f")` is `2.67`, from the exact binary value. Row 14 is the threshold: `str(1e15)` is positional and `str(1e16)` is the first exponent form, one digit later than Ruby, and the exponent form has no `.0` (`1e+20`). Row 15 is `round(1250, -2)` giving `1200` — banker's rounding again — and `round(x, -2)` on a float staying a float.

```ruby
# Kata: a price table — names left-aligned, amounts right-aligned with
# thousands separators and two decimals — from format and one gsub.

def money(x) = format("%.2f", x).gsub(/\B(?=(\d{3})+\.)/, ",")

items = { "laptop" => 1299.99, "mouse" => 24.5, "desk" => 1234567.891, "refund" => -1234.5 }
items.each { |name, price| puts format("%-8s %14s", name, money(price)) }
puts format("%-8s %14s", "total", money(items.values.sum))
```
