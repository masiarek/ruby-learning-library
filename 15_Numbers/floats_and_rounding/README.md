# `0.1 + 0.2 != 0.3`, and `2.5.round` is `3`

**Level:** 201 · anyone who has trusted a Float with money

**One line:** A Ruby Float is the same 64-bit double as a Python float — `0.1 + 0.2` is `0.30000000000000004` in both — but `2.5.round` is `3` where Python's `round(2.5)` is `2`, overflow gives `Infinity` where Python raises, and `max` with a NaN raises where Python quietly picks by order.

A Float holds a binary fraction, and `0.1`, `0.2` and `0.3` are not binary fractions: each literal is the nearest double, the sum of two nearest doubles is not the nearest double to `0.3`, and `==` says so. That part is IEEE 754 and identical in every language that uses doubles. What a language adds is its rounding rule and its policy at the edges. Ruby rounds a half away from zero by default and offers `half: :even`, `half: :down` and `half: :up` as options; it rounds to `ndigits` by scaling, so `2.675.round(2)` is `2.68` even though the Float is a hair below 2.675. Overflow is `Float::INFINITY`, not an error. NaN is unequal to itself, and `max` or `sort` over an array with a NaN in it raises `ArgumentError` rather than return an order-dependent answer. And `to_r` shows the exact value a Float holds, while `rationalize` recovers the short fraction you probably meant.

## Reading the output

Rows 1–3 are the binary fraction. `0.1 + 0.2` prints as `0.30000000000000004`, the shortest decimal that reads back as that double, and it is not `== 0.3`; rounding to two places gives a Float that is (row 2). Row 3 measures the miss: `5.55e-17`, a quarter of `Float::EPSILON`, which is the gap between `1.0` and the next Float — a useful yardstick only near `1.0`, which is why a tolerance should scale with the numbers (the second exercise below).

Rows 4–8 are rounding. `2.5.round` is `3` and `-2.5.round` is `-3`: a half goes away from zero, and the result is an Integer. `half: :even` gives banker's rounding, `2` for `2.5` and `4` for `3.5`. Row 6 is the one to remember: `2.675` is stored as `2.67499999999999982236`, yet `2.675.round(2)` is `2.68`, because Ruby scales first — `2.675 * 100` is exactly `267.5` in Float arithmetic — and rounds that half up. Row 7 is a true half, `0.125`, which is exact in binary, rounded away from zero to `0.13`. `floor` and `ceil` take a digits argument too, and a negative `ndigits` rounds to tens and hundreds, returning an Integer.

Rows 9–10 are the limits. `Float::EPSILON`, `MAX`, `MIN`, `DIG` (15 decimal digits survive a round trip) and `MANT_DIG` (53 bits of significand) are the constants of a double; `2.0 ** 1024` and `Float::MAX * 10` overflow to `Infinity` without a word. Rows 11–13 are NaN: unequal to itself, `<=>` gives `nil`, but `[nan].include?(nan)` and `[nan] == [nan]` are `true` because Array compares identity before calling `==` — and `[1.0, nan].max` raises, since no order contains a NaN. Rows 14–17 show what a Float really holds: `0.1.to_r` is the exact fraction `3602879701896397/36028797018963968`, `rationalize` with a tolerance recovers `(1/10)`, `1e16 + 1` is `1e16` because the doubles are two apart there, and `next_float` walks to the neighbouring double.

## Compared with Python

Same bits, different rules. Rows 1–3 agree to the last digit, and Python adds `math.isclose`, whose default tolerance is relative. Rows 4–7 are the differences a Python programmer must unlearn in Ruby: `round()` is banker's rounding and nothing else — the row 5 twin reaches for `decimal` with `ROUND_HALF_UP` to get Ruby's default — and `round(2.675, 2)` is `2.67`, because Python rounds the exact binary value rather than a scaled one, so a stored value below the half goes down. `0.125` goes to even, `0.12`. `floor` has no digits argument, and `round(1234.567, -2)` stays a float. Row 10 is the loud difference: `2.0 ** 1024` raises `OverflowError` (multiplication by `10` does not — it returns `inf`), where Ruby answers `Infinity`. Row 13 is the quiet one: `max(1.0, nan)` is `1.0` and `max(nan, 1.0)` is `nan`, no error, because `max` keeps the first value unless a later one compares greater and a NaN never does; Ruby refuses. `Fraction(0.1)`, `limit_denominator`, `math.nextafter` and `math.ulp` are the names of `to_r`, `rationalize` and `next_float`. The `decimal` module is where Python keeps rounding modes and decimal arithmetic; its Ruby counterpart, `BigDecimal`, is the next lesson.
