# A method is a value once you ask for it

**Level:** 301 · someone who has used `send` and `define_method` and wants the objects behind them

**One line:** `obj.method(:name)` hands back a `Method` bound to `obj`, and `Klass.instance_method(:name)` an `UnboundMethod` you can bind to any instance of `Klass` later — Python has bound methods too, but `Cls.f` is a plain function and `types.MethodType` binds it to anything without checking.

A Ruby method is not an object while it sits in a class; it becomes one when you ask. `obj.method(:name)` looks the name up the way a call would and wraps what it finds in a `Method` that remembers three things: the code, the object it was found on (`receiver`) and the class or module that defined it (`owner`). Call it with `call`, with `.()` or with `[]`, all three are the same call. `arity` is negative when parameters are optional (`-2` means one required and at least one more allowed), and `parameters` lists every parameter with its kind, which is what a library uses to decide how to call something it was handed.

`unbind` takes the receiver away and leaves an `UnboundMethod`, the same object `Klass.instance_method(:name)` returns directly. Binding it back is type-checked: `bind` accepts only an instance of the owner or one of its subclasses and raises `TypeError` for anything else. When the instance belongs to a subclass that overrides the method, the *owner's* version runs anyway — binding is a way to reach past an override. `bind_call(obj, *args)` binds and calls without the intermediate object. `super_method` walks up one step of the same lookup `super` would take, `original_name` sees through an alias, `to_proc` produces a lambda so `&obj.method(:name)` slots a method into `map`, and `method(:puts)` on `main` shows that even the top-level printing functions are methods with an owner (`Kernel`).

## Reading the output

Rows 1–5 are the bound `Method`: its class, the three call spellings, `name`/`owner`, `receiver` (the very object, `equal?` is true) and `arity`/`parameters` (`-2`: one required, one optional). Row 6 unbinds it and shows that `Greeter.instance_method(:greet)` is an equal `UnboundMethod`. Rows 7–9 bind it again: to another `Greeter`, with `bind(...).call` and with `bind_call`; to a `String`, which is refused with `TypeError`; and to a `Loud`, a subclass that overrides `greet` — the output is `Greeter`'s lower-case version, not `Loud`'s upper-case one, because the *unbound method* decides which code runs, not the receiver's class.

Rows 10–12 walk the lookup chain by hand: `eve.method(:greet)` is owned by `Loud`, its `super_method` by `Greeter`, calling that gives the un-shouted greeting, and one more `super_method` is `nil` because nothing above `Greeter` defines `greet`. Rows 13–14 turn the method into a lambda-style `Proc` and pass it with `&`. Row 15: an alias keeps its own `name` but `original_name` is the method it was copied from. Row 16: every `method(:greet)` call allocates a new `Method` — equal by `==`, never `equal?`. Rows 17–19: `puts` is owned by `Kernel` and its receiver is `main`; `+` on an Integer is a method like any other, so `1.method(:+)` maps over an array.

## Compared with Python

Python's `obj.f` is also created on access: row 16 shows `m == ada.greet` is `True` while `m is ada.greet` is `False`, the same pair as Ruby. A bound method carries `__self__` (the receiver, row 4) and `__func__` (row 6), and `__func__ is Greeter.greet` because in Python 3 the class attribute is the plain function itself — there is no unbound-method type, so there is nothing to `unbind` (row 6 prints `function`). Where Ruby type-checks `bind`, Python checks nothing: `Greeter.greet("a string", "Yo")` runs until the body asks the string for `.name` and fails with `AttributeError` (row 8), and `types.MethodType(func, obj)` binds a function to any object at all (row 7). Calling `Greeter.greet(eve, ...)` on a `Loud` instance reaches past the override exactly as Ruby's row 9 does.

`super(Loud, eve).greet` is the counterpart of `super_method` (rows 10–11), but at the top of the chain it raises `AttributeError` instead of returning `None` (row 12). An alias is the same function object (row 15, `is` is `True`), so Python has no `original_name` to recover. `inspect.signature` stands in for `parameters` (row 5) and reports kinds by name; there is no `arity` because a signature is a richer object. `print` is a `builtin_function_or_method` with a module and no owner class (row 17), and `(1).__add__` is a `method-wrapper` around the C slot (row 18) — Python spells "operators are methods" through dunder names, Ruby through `1.method(:+)`.

```ruby
# Kata: describe any Method or UnboundMethod in one line -- its name, its
# owner, how many required and optional positional parameters it takes,
# and whether it is bound to a receiver.

class Greeter
  def initialize(name)
    @name = name
  end

  def greet(greeting, punct = "!")
    "#{greeting}, #{@name}#{punct}"
  end

  def inspect
    "#<Greeter #{@name}>"
  end
end

def describe(m)
  kinds = m.parameters.map(&:first)
  required = kinds.count(:req)
  optional = kinds.count(:opt)
  bound = m.respond_to?(:receiver) ? "bound to #{m.receiver.inspect}" : "unbound"
  format("%-6s from %-8s required=%d optional=%d  %s", m.name, m.owner, required, optional, bound)
end

puts describe(Greeter.new("Ada").method(:greet))
puts describe(Greeter.instance_method(:greet))
puts describe(1.method(:+))
puts describe(method(:puts))
puts describe(Array.instance_method(:push))
```
