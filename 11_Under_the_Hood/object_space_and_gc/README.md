# The GC answers comparisons, not counts

**Level:** 301 · someone who has asked "when does Ruby free this?" and wants to know which answers are promises

**One line:** `GC.start`, `GC.stat`, `ObjectSpace` and `WeakRef` let a program watch its own heap, but only comparisons are stable — a `WeakRef` may or may not be dead after `GC.start` and a finalizer runs at exit at the latest — while CPython's reference counting frees an object, and runs its `__del__`, the moment the last reference goes.

Ruby's collector is a generational mark-and-sweep: it starts from the roots (constants, globals, every live stack frame), marks what it can reach and sweeps the rest, in small "minor" passes that look only at young objects and occasional "major" ones that look at everything (row 10). It scans the machine stack *conservatively* — any word that looks like a pointer keeps its object alive — which is why the page cannot promise when an object dies. What it can promise is monotonic counters and booleans: `GC.start` runs a full collection and `GC.count` goes up (row 1); `GC.stat(:total_allocated_objects)` is a running total that grows by at least the thousand strings we kept (row 2); `GC.disable` and `GC.enable` return the previous state (row 3); `GC.latest_gc_info` says why the last collection ran (row 12). `ObjectSpace.each_object(Widget)` enumerates every live instance (row 4 prints only `any?`, because how many *dead* ones are still sitting in the heap depends on when the last sweep ran).

`ObjectSpace::WeakMap` (row 5) and `WeakRef` (rows 6–7) hold an object without keeping it alive. Row 7 is the whole point of the page: after `w = nil; GC.start`, `weakref_alive?` is either `nil` or `true`, and the page prints only that it is one of the two — a stale copy of the reference may still be on the stack, so a program that uses a `WeakRef` must check `weakref_alive?` and rescue `WeakRef::RefError` rather than reason about *when*. A finalizer (row 8) is a proc that runs after its object is collected, or at exit if it never was: the line it prints appears after row 13, and the proc must not mention the object, or the object can never die. Ruby keeps no reference counts at all — `ObjectSpace.count_objects` counts heap slots by type (row 9) — and Integers, Symbols, `nil`, `true`, `false` and most Floats are *immediates* that need no heap slot: `1.object_id` is the same number every time, while two `"a"` literals are two objects (row 11). The `objspace` extension adds per-object sizes (row 13).

## Reading the output

Rows 1–3 are the counters and switches; every value is a comparison against a reading taken a moment earlier, never the reading itself. Row 4 goes from `false` to `true` when the first `Widget` is made. Rows 5–6 show a weak map and a weak reference behaving like strong ones while the object is referenced. Row 7 is `true` for "nil or true": the program does not know which, and neither should you. Row 8 is what `define_finalizer` returns, an `[Integer, Proc]` pair; the finalizer's own line is the last line of the output, after row 13, printed while the process exits. Rows 9–10 and 12 are membership checks on the statistics hashes. Row 11 is the immediate-versus-heap distinction: `[true, false]`. Row 13: a thousand-character string is bigger than a thousand bytes.

## Compared with Python

CPython frees an object the instant its reference count reaches zero, so the events Ruby cannot schedule happen on a predictable line: `del w` in row 7 makes the weak reference dead *at once*, and the log shows `__del__` had already run before the row printed. `sys.getrefcount` (row 9) is printed as comparisons only — the absolute number includes the call's own argument, and Python 3.12 made `None`, small integers and other "immortal" objects report a fixed count. The `gc` module is not the memory manager; it is only the *cycle* collector, there for the one thing counting cannot free: row 12 makes two objects point at each other, deletes both names, and they survive until `gc.collect()` finds them. It is generational with three generations (row 10) and tracks only container objects — an `int` or a `str` cannot be part of a cycle, so it is not tracked (row 11). `gc.collect()` returns how many unreachable objects it found (row 1, printed as `>= 0`), `gc.get_objects()` lists the tracked ones (rows 2 and 4), `weakref.WeakValueDictionary` is the weak map (row 5), and `weakref.finalize` (row 8) runs at exit if the object is still alive, so its line follows row 13 exactly as Ruby's finalizer does. `sys.getsizeof` is `memsize_of` (row 13). Two things the twin does not print because the two CI Pythons disagree: `gc.get_threshold()` (700 in 3.12, 2000 since the 3.13 incremental collector) and `sys._is_gil_enabled()`, which exists only from 3.13. *(Not machine-checked here.)*

## Try it

1. Write `allocations { … }` that returns how many objects a block allocated, from `GC.stat(:total_allocated_objects)` before and after with the collector disabled in between. Print *comparisons*: a hundred `String.new` calls allocate at least a hundred objects, `1 + 2` allocates no more than an empty block does, and `[[1], [2], [3]]` allocates at least four. Say in a comment why you would not print the raw numbers.
2. Give `Widget` a finalizer whose proc closes over the widget itself, and show with `ObjectSpace.each_object(Widget).any?` after several `GC.start` calls that it is never collected. Then fix it with a class method `Widget.finalizer_for(name)` that returns a proc holding only the name.

*[`object_space_and_gc_kata_rb.rb`](examples/object_space_and_gc_kata_rb.rb) in full — pasted here by `tools/run_examples.py` from the file CI runs.*

```ruby
# Kata: count what a block allocates. GC.stat(:total_allocated_objects) is a
# running total, so its difference across a block is the block's allocations.
# Only comparisons are printed: an exact count is an implementation detail
# (the first call of `allocations` itself allocates one object, a call cache,
# which is why it is called once to warm up before anything is measured).

def allocations
  GC.disable
  before = GC.stat(:total_allocated_objects)
  yield
  GC.stat(:total_allocated_objects) - before
ensure
  GC.enable
end

allocations { }
empty = allocations { }
strings = allocations { 100.times { String.new("s") } }
arithmetic = allocations { 1 + 2 }
symbol = allocations { :sym }
arrays = allocations { [[1], [2], [3]] }

puts "1. an empty block allocates nothing:                    #{empty == 0}"
puts "2. 100 String.new calls allocate at least 100 objects:  #{strings >= 100}"
puts "3. 1 + 2 allocates nothing (Integers are immediates):   #{arithmetic == 0}"
puts "4. a symbol literal allocates nothing:                  #{symbol == 0}"
puts "5. [[1], [2], [3]] allocates at least 4 objects:        #{arrays >= 4}"
```
