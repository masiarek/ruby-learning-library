# Most loops you would write are one Enumerable call

**Level:** 201 · anyone who has written `each` with an accumulator and suspects there is a method for that

**One line:** `map`, `select`, `reject`, `find`, `partition`, `group_by`, `tally`, `each_slice`, `each_cons`, `zip`, `flat_map`, `sum`, `minmax`, `chunk_while`, `each_with_index`, `filter_map` and `sort_by` each replace one shape of loop, and Python spells the same thirty rows with comprehensions, builtins, `itertools` and `collections` — with one trap: `itertools.groupby` is Ruby's `chunk`, not its `group_by`.

Every method below is a loop shape with a name. `map` is "build a list of the block's results", `select` is "keep the ones where the block is true", `group_by` is "a hash from the block's value to the items that gave it", `each_cons(2)` is "every neighbouring pair", `chunk_while` is "split where the block stops holding". Reaching for the name instead of the loop is most of what reads as idiomatic Ruby, and because they all come from `Enumerable` they work on anything with `each` — arrays here, but equally a Hash, a Range, a Set or [your own class](../enumerable_is_a_mixin/README.md). Two collections run through thirty of them, six or so per group, so the rows can be read side by side with the Python twin.

## Reading the output

Rows 1–6, transform, keep, drop, find: `map` returns a new array of the block's values; `select` keeps, `reject` drops, and `filter` is the very same method as `select` (row 2 prints that the two `UnboundMethod`s are equal, not merely alike). `find` returns the first hit or `nil` (row 4); `partition` returns both halves at once (row 5); `filter_map` is a `map` whose `nil` results are dropped (row 6), so one block does the keeping and the transforming.

Rows 7–11, group and count: `group_by` builds a hash whose keys are the block's values in first-seen order, and whose values keep the input order; row 8 groups an *unsorted* list into two buckets, because `group_by` does not care about neighbours. `chunk` (row 9) does care: it cuts the list into runs of neighbours that give the same block value, so the same input yields four runs — that is the method Python's `itertools.groupby` corresponds to. `tally` (row 10) counts occurrences into a hash, again in first-seen order, and `count` takes a block.

Rows 12–17, windows and slices: `each_slice(3)` cuts into non-overlapping pieces and `each_cons(2)` slides a window; `chunk_while { |a, b| b == a + 1 }` and `slice_when { |a, b| b != a + 1 }` are the same cut described from opposite sides (rows 14 and 15 agree). `zip` pairs positions; `flat_map` maps and flattens one level.

Rows 18–19, numbering: `each_with_index` yields the index second, and `map.with_index(1)` — `map` without a block returns an Enumerator, and `with_index` takes a starting offset — is how a one-based numbering is written. Rows 20–23 reduce to a value: `sum` takes a block, `minmax` returns a pair, `min(2)` and `max(2)` return the two smallest and two largest, and `any?`/`all?`/`none?` accept a pattern instead of a block — `all?(Integer)` matches the way `case` does, with `===` *(Not machine-checked here.)*.

Rows 24–28, order and slice: `sort_by` with an array key sorts by the first element and breaks ties by the second, so `[w.size, w]` is "by length, then alphabetically" and `[-w.size, w]` reverses only the first criterion. `take_while`/`drop_while` split at the first failing element, `uniq` keeps first occurrences, and `cycle` repeats forever, which is why the row takes `first(8)`. Rows 29–30 are two spellings Python does not have: `to_h` with a block builds a hash from pairs, and `grep` selects with `===`, so a Regexp, a Range or a Class all work as the pattern.

## Compared with Python

Python's loop shapes are mostly *syntax*: a comprehension with an `if` does `select`, `reject` and `filter_map` (rows 2, 3 and 6 are one form), `next(genexp, None)` is `find` (row 4), and `partition` is two comprehensions (row 5). The rest is spread over four homes: builtins (`sorted`, `min`, `max`, `sum`, `zip`, `enumerate`, `any`, `all`), `itertools` (`batched` for `each_slice` — new in 3.12 — `pairwise` for `each_cons(2)`, `takewhile`, `dropwhile`, `cycle`, `islice`, `chain.from_iterable` for `flat_map`), `collections` (`Counter` for `tally`, `defaultdict(list)` for `group_by`) and `heapq` (`nsmallest`/`nlargest` for `min(2)`/`max(2)`, row 22).

The trap is rows 7–9. Python has no `group_by`; the loop over a `defaultdict(list)` in row 7 is the idiom. `itertools.groupby` looks like the answer but groups *consecutive* runs, so on the unsorted list in row 8 it returns four groups where Ruby's `group_by` returned two — it is Ruby's `chunk`, and row 9 shows the standard fix: sort by the key first, which also changes the order of the groups (`False` before `True`). `pairwise` gives only pairs; a wider window such as `each_cons(3)` needs a loop or a `collections.deque` *(Not machine-checked here.)*. `chunk_while` and `slice_when` have no counterpart at all, so rows 14–15 use a five-line `runs` helper, and `grep` becomes a comprehension with `re.search` or a range test (row 30). What Python *does* have that reads the same way: `sorted` with a tuple key (rows 24–25) breaks ties exactly as Ruby's array key does, and `enumerate(words, 1)` is `with_index(1)`.

## Try it

1. Ten days of temperature readings, `[12, 15, 15, 9, 21, 22, 22, 22, 18, 7]`: print, one Enumerable call each, the days above 20 with their index, the runs of non-decreasing readings, the day-to-day changes, the three-day moving averages, how often each reading occurs, the most frequent reading, the readings in groups of four, the coldest and warmest, the readings sorted by distance from 15 (ties broken by value), and the first warm day together with the days before it.
2. Rewrite the same ten rows in Python. Which need `itertools.pairwise`, which `batched`, which a `Counter` — and which of them have no standard-library spelling and need a loop? Check the three-day averages: `pairwise` will not do it.

```ruby
# Kata: ten questions about a week and a half of temperature readings,
# each answered by one Enumerable method.
def row(n, label, value) = puts(format("%2d. %-46s %s", n, label, value.inspect))

temps = [12, 15, 15, 9, 21, 22, 22, 22, 18, 7]

row 1,  "days above 20, with their index", temps.each_with_index.select { |t, _| t > 20 }.map { |t, i| "day #{i}: #{t}" }
row 2,  "runs of non-decreasing readings", temps.chunk_while { |a, b| b >= a }.to_a
row 3,  "day-to-day changes", temps.each_cons(2).map { |a, b| b - a }
row 4,  "three-day moving averages", temps.each_cons(3).map { |w| (w.sum / 3.0).round(1) }
row 5,  "how often each reading occurs", temps.tally
row 6,  "the most frequent reading", temps.tally.max_by { |_, n| n }.first
row 7,  "readings in groups of four", temps.each_slice(4).to_a
row 8,  "coldest and warmest", temps.minmax
row 9,  "readings sorted by distance from 15", temps.sort_by { |t| [(t - 15).abs, t] }
row 10, "first warm day, and the days before it", [temps.find { |t| t > 20 }, temps.take_while { |t| t <= 20 }]
```
