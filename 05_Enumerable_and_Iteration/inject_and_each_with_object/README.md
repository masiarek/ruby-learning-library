# `inject` makes the block's value the next accumulator

**Level:** 201 · anyone who has written `inject({}) { |h, x| h[x] = … }` and been told an Integer has no `[]=`

**One line:** `inject` feeds each block result back in as the accumulator, so a block that ends in an assignment hands the next round a number instead of the hash; `each_with_object` returns the memo whatever the block returns; and `sum` is not `inject(:+)` on floats — Ruby's `sum` compensates rounding, so `[0.1] * 10` sums to `1.0` where `inject(:+)` gives `0.9999999999999999`, and since 3.12 Python's `sum` does the same while `functools.reduce` does not.

A fold walks a collection carrying one value along. In `inject` that value is whatever the block returned last time: the block receives `(accumulator, element)` and its return value *is* the next accumulator, which is exactly right for `acc + x` and exactly wrong for `h[x] = v`, whose value is `v`. `each_with_object(memo)` fixes the shape by handing the same memo object to every call — as `(element, memo)`, note the reversed order — and returning that object at the end, so the block may return anything, but it must *mutate* the memo rather than rebind it. `sum` looks like a third spelling of `inject(:+)` and is not: for Floats the docs say it uses Kahan-Babuska compensated summation, which keeps the rounding error of each addition in a second variable and folds it back in *(the algorithm's name is not machine-checked here; its results are, in rows 10–13)*.

## Reading the output

Rows 1–9, the forms of `inject`: a symbol names the method to fold with — `:+`, `:*`, `:lcm`, `:gcd`, any binary method (row 9) — a block spells it out, and an initial value goes first (`inject(10, :+)`, row 3). `reduce` is not a copy but the same method under a second name: row 5 prints that the two `UnboundMethod` objects are equal. Without an initial value the first element *is* the first accumulator, so an empty array folds to `nil` (row 6, where `sum` gives `0`), and a one-element array returns its element without calling the block at all (row 7 — that block would raise). Row 8 uses the same rule: the fold keeps the longer of the running best and each word.

Rows 10–14, `sum` versus `inject(:+)`: ten copies of `0.1` add up to `0.9999999999999999` one addition at a time and to `1.0` under `sum`; `1e100 + 1.0 - 1e100` loses the `1.0` entirely in `inject` and keeps it in `sum` (row 12); `0.1 + 0.2 + 0.3` is off by one unit in the last place in `inject` and exact in `sum` (row 13). Row 14 is the other half of `sum`: with non-float elements it is ordinary exact arithmetic (a `Rational` stays a Rational), and an initial `0.0` makes the result a Float.

Rows 15–22, `each_with_object`: rows 15 and 16 build the same hash, and the `inject` version needs the trailing `; h` to return the accumulator. Row 17 is what happens without it — the block's value is `10`, so `10` becomes the accumulator and the next round calls `10[2] = 20`. Row 18 shows why `acc << x` does not need the trick: `<<` returns its receiver. Row 19 is the second trap, the argument order: `each_with_object` yields `|element, memo|` and `inject` yields `|memo, element|`. Rows 20–21 are the memo's rule: the block's return value is ignored (`:ignored` does no harm), but `acc += w` rebinds the block parameter to a new string and the memo comes back empty, where `acc << w` mutates it and the memo comes back full. Row 22 is the counting idiom with a default-valued Hash; `tally` does the same in one word.

Rows 23–25: `sum("")` and `inject(:+)` both concatenate strings, `inject(:+)` and `sum([])` both concatenate arrays, and a block can destructure its element with `(x, i)` when the elements are pairs.

## Compared with Python

`functools.reduce` is `inject` under the same rules: the function gets `(accumulator, element)`, its return value is the next accumulator, the initial value is an optional third argument, one element comes back without a call (row 7), and an empty iterable with no initial value raises `TypeError` where Ruby returns `nil` (row 6). It was a builtin in Python 2 and now lives in `functools` *(Not machine-checked here.)* — row 5 prints that `builtins` has no `reduce`. The `inject({})` trap reproduces exactly in row 17: a function that assigns and returns `None` makes `None` the accumulator, and the next round fails with `TypeError`.

Python has no `each_with_object`, and does not need one: a `for` loop has no scope of its own, so `sizes[w] = len(w)` and even `text += w` work on the outer variable (rows 15, 20 and 21) — where Ruby's `acc += w` inside a block rebinds the block parameter and loses the work. Rows 10–13 hold the measured surprise. Python's `sum` compensates rounding too — the 3.12 release notes introduced it as Neumaier summation *(that attribution is not machine-checked here; the values are, under both 3.12 and 3.14)* — so `sum([0.1] * 10)` is `1.0`, the same as Ruby's `sum`, and `math.fsum` — the older tool, which returns the correctly rounded exact sum — agrees; the naive `0.9999999999999999` now belongs to `reduce(operator.add, …)` only. Row 14 shows `sum` staying exact with `Fraction`, and rows 23–24 the two rules Ruby lacks: `sum` refuses strings outright (`"".join` is the answer), and although `sum(lists, [])` works, `itertools.chain.from_iterable` is the idiom.

Why `0.1` ten times is not `1.0` in the first place is the Python library's [Float equality and NaN ↗](https://masiarek.github.io/python-learning-library/03_Numbers/float_equality_and_nan/index.html) page, and the Math library's [Machine numbers ↗](https://masiarek.github.io/math-learning-library/01_Precision/machine_numbers/index.html) explains the rounding that compensated summation undoes.

## Try it

1. Write seven folds with `inject` or `each_with_object` and nothing else: the product of `1..6`, the longest word in a list, a hash from word to length, the running totals of `[3, 1, 4, 1, 5]`, a reversed copy of `[1, 2, 3]`, the words grouped by first letter (a `Hash.new { |h, k| h[k] = [] }` as the memo), and `[0.1] * 10` summed by `inject` and then by `sum`.
2. Implement compensated summation yourself: `inject([0.0, 0.0]) { |(sum, err), x| … }` carrying the running sum and the accumulated rounding error, then compare your result with `Array#sum` on `[0.1] * 10` and on `[1e100, 1.0, -1e100]`. The second one is the hard case: which of the two does your version get right?

# Kata: seven folds, each written with inject or each_with_object and nothing else.
def row(n, label, value) = puts(format("%2d. %-44s %s", n, label, value.inspect))

words = %w[pear fig apple plum kiwi]

row 1, "product of 1..6", (1..6).inject(:*)
row 2, "the longest word", words.inject { |best, w| w.size > best.size ? w : best }
row 3, "word => size, with each_with_object", words.each_with_object({}) { |w, h| h[w] = w.size }
