# A Fiber is a coroutine you resume by hand

**Level:** 301 · anyone who has written a Python generator and wants the object Ruby built `Enumerator#next` on

**One line:** `Fiber.new { }` makes a block that runs only when you `resume` it and stops wherever it calls `Fiber.yield`; values travel in through `resume` and out through `yield`, nothing switches fibers except those two calls, and a finished fiber raises `FiberError` — the protocol of a Python generator's `next`, `send` and `throw`, on an object that is not tied to a `def` with `yield` in it.

A fiber is a coroutine: a block with its own stack that runs only while somebody is resuming it. The first `resume(x)` starts the block with `x` as its parameter; inside, `Fiber.yield(v)` suspends the fiber and makes `v` the value of that `resume` call in the caller; the next `resume(w)` continues the block with `w` as the value of the `Fiber.yield` expression (rows 1 and 3). When the block ends, its last expression is the value of the final `resume` (row 4) and `alive?` turns `false` (row 5); resuming again is a `FiberError` (row 6), and so is calling `Fiber.yield` from the root fiber, which has nowhere to yield to (row 7). `Fiber#raise` resumes the fiber by raising inside it, at its `Fiber.yield` (row 8); `Fiber#kill` (Ruby 3.3) unwinds it, running its `ensure` blocks (row 13). Several values go through as several arguments and come back as an array (row 14).

There is no scheduler and no preemption. Row 12 logs an outer fiber resuming an inner one twice: every line lands exactly where the `resume` and `Fiber.yield` calls put it, and no timer ever moves control. A fiber runs on whatever thread resumes it (row 10) and is not a thread — `Fiber.current` inside the block is a new object, while at the top level it is the root fiber the thread started with (row 9). That makes a fiber a generator (row 11: an endless loop that yields Fibonacci numbers, resumed eight times) and, with a scheduler installed through `Fiber.set_scheduler`, the unit of non-blocking I/O that the `async` gem builds on — `Fiber.scheduler` is `nil` here because nothing was installed (row 15) *(Not machine-checked here.)*. The next page shows that `Enumerator#next` is exactly this: a fiber wrapped around the enumerator's block.

## Reading the output

Rows 1 to 5 are one fiber's life. `resume(1)` gives the block `x = 1` and gets back `2` from `Fiber.yield x * 2`; `resume(10)` makes that `Fiber.yield` return `10`, so `y + 1` is `11`; `resume(100)` makes the second yield return `100` and the block ends with `"done 100"`, which is the value of that last `resume`. Between yields `alive?` is `true`; after the block ends it is `false`. Rows 6 and 7 print the two messages: `attempt to resume a terminated fiber` and `attempt to yield on a not resumed fiber`.

Row 8 shows `Fiber#raise`: the fiber was suspended at `Fiber.yield 1`, the `RuntimeError` appeared there, the block's `rescue` returned a string, and that string is the value of the `raise` call — after which the fiber is finished. Rows 9 and 10 place a fiber: `Fiber.current` at the top level is the root fiber, inside the block it is another `Fiber`, and both run on the main thread. Row 11 is the generator idiom, row 12 the proof that nothing moves control but `resume` and `yield`, row 13 that `kill` runs the `ensure`, and row 14 that `resume(1, 2)` becomes two block parameters while `Fiber.yield 1, 2` comes back as `[1, 2]`. Row 15 prints `nil`: no fiber scheduler is installed.

## Compared with Python

A Python generator is the same coroutine with `yield` as the marker: `next(g)` is the first `resume`, `g.send(v)` a `resume(v)`, and the `yield` *expression* inside evaluates to what `send` passed (row 3). The differences are at the ends. A generator's *return* value does not come back from `send` — it rides on `StopIteration.value` (row 4), and every later `next` raises `StopIteration` again with `None` (row 6); Ruby gives the last value directly and then raises `FiberError`. There is no `alive?`: `inspect.getgeneratorstate` answers with `GEN_CREATED`, `GEN_SUSPENDED` or `GEN_CLOSED` (rows 2 and 5). `g.throw(exc)` is `Fiber#raise` (row 8); `g.close()` is `Fiber#kill`, raising `GeneratorExit` at the yield so that `finally` runs (row 13). A `yield` outside a function is a `SyntaxError` at compile time (row 7), where Ruby's `Fiber.yield` at the top level fails at run time.

A generator is not a separate object from its frame — there is no `Fiber.current`, only a `generator` whose `gi_frame` is a suspended frame (row 9), on the caller's thread (row 10). Everything else lines up: the Fibonacci generator (row 11), the nested log with no preemption (row 12), and several values as one tuple each way (row 14). Row 15 is Python's extra: an `async def` coroutine is the same machine, and `c.send(None)` drives it to its `StopIteration` without an event loop — `asyncio` is a scheduler for these objects, as Ruby's `Fiber.scheduler` is for fibers.

## Try it

1. Write a fiber that keeps a running total of the numbers it is resumed with and yields the total after each one. Resume it with 1 to 5 and print each total; then print whether the fiber is still alive and say why.
2. Build a two-fiber ping-pong: fiber A yields `"ping n"` and fiber B yields `"pong n"`, and a loop in the root fiber resumes them alternately five times, printing each value. Then explain why neither fiber can resume the other directly while the root fiber is resuming it (`Fiber#transfer` is the answer to look up).

<!-- source:fibers_are_coroutines_kata_rb -->
*[`fibers_are_coroutines_kata_rb.rb`](examples/fibers_are_coroutines_kata_rb.rb) in full — pasted here by `tools/run_examples.py` from the file CI runs.*

```ruby
# Kata: a fiber that keeps a running total of the numbers it is resumed with.
# The first resume hands the block its parameter; every later resume becomes
# the value of Fiber.yield inside the loop.
total = Fiber.new do |n|
  sum = 0
  loop do
    sum += n
    n = Fiber.yield sum
  end
end

(1..5).each { |i| puts "resume(#{i}) -> running total #{total.resume(i)}" }
puts "alive? #{total.alive?} (the loop never ends; the fiber is only suspended)"
```
