# `x ||= v` assigns when `x` is nil or false

**Level:** 201 · anyone who has written `@cache ||= compute`

**One line:** `x ||= v` is `x || (x = v)`: it assigns when `x` is `nil` *or* `false` and leaves every other value alone, so it memoizes a `false` result by recomputing it every call — while Python's `x = x or v` replaces `0` and `""` as well, and `functools.cache` remembers a `False` without complaint.

Ruby has exactly two false values, `nil` and `false`, and `||` returns its left operand whenever that operand is not one of them. `x ||= v` is sugar for `x || (x = v)`, so the assignment happens only for those two values; `0`, `""` and `[]` are all truthy and stay put. That makes `||=` the idiom for defaults and for memoization — `@cache ||= compute` runs `compute` once and returns the stored value ever after — with one hole: a stored `false` (or `nil`) looks exactly like "not computed yet" and is recomputed on every call. The `defined?(@ivar)` guard closes the hole. The program below runs each of those, then the cousins: `&&=`, the `(h[:k] ||= []) << x` grouping idiom, `nil.to_a` and `Array()`, `fetch` with a default, and `||` against `or`.

## Reading the output

- **Rows 1–4** are the operator on four values. `nil` and `false` are replaced; `0` and `""` are kept because they are truthy in Ruby — the row a Python programmer expects to come out the other way.
- **Row 5** is the memoization idiom working: three calls, one computation.
- **Row 6** is the trap: the computed value is `false`, so every call sees a false `@flag` and computes again — three calls, three computations. **Row 7** guards on `defined?(@right)` instead, which asks whether the variable has been assigned, not what it holds, and computes once.
- **Row 8**: `&&=` is the mirror image; it assigns only when the variable is truthy, so `nil` stays `nil`.
- **Row 9** is the grouping idiom: `(h[:k] ||= [])` creates the array on the first access and returns the existing one after that, so `<<` appends to the same array both times.
- **Row 10**: `nil.to_a` and `Array(nil)` are both `[]`, which is why `Array(x).each` is a nil-safe loop; `Array([1])` leaves an array alone and `Array(1..2)` expands a range.
- **Row 11**: `h[:z]` is `nil` for a missing key with no error, `fetch` takes a default, and `fetch` with a block computes one from the key.
- **Row 12**: `p2 = nil or 5` leaves `p2` as `nil` because `or` binds *below* `=`, so it parsed as `(p2 = nil) or 5`. Use `||` in expressions and `or` only for control flow.

## Compared with Python

Python has no `||=` and no `&&=`. The nearest idiom, `x = x or 5`, uses Python's `or`, which — like Ruby's — returns an operand rather than a boolean, but Python's falsy set is larger: `None`, `False`, `0`, `0.0`, `""`, `[]`, `{}` and every empty container. So rows 3 and 4 flip: `0` and `""` are replaced, which is the classic Python bug when a count of zero or an empty string is a legitimate value. The fix is `x if x is not None else 5`, or a walrus in an expression. Memoization goes through `functools.cache` on a function or `functools.cached_property` on a method, and neither has Ruby's hole: they store the *result*, `False` included, rather than testing it for truth (rows 6 and 7). `dict.setdefault` is `(h[:k] ||= [])`, `dict.get` is `fetch` with a default, and there is no `list(None)` — it raises — so the nil-safe loop idiom is `x or []`. Row 12 is the same expression twice because Python's `or` has ordinary precedence.

# Kata: memoize a computed boolean correctly.
# `@verbose ||= compute` recomputes whenever the cached value is false, because
# `||=` cannot tell "false" from "never computed". Guard on `defined?` instead.

class Settings
  attr_reader :runs

  def initialize
    @runs = 0
  end

  def verbose_with_or_equals
    @verbose_a ||= compute_verbose
  end

  def verbose_with_defined
    return @verbose_b if defined?(@verbose_b)
    @verbose_b = compute_verbose
  end

  private

  def compute_verbose
    @runs += 1
    false # the setting is off, and that answer should be remembered
  end
end

s = Settings.new
3.times { s.verbose_with_or_equals }
puts "||= version, three reads: computed #{s.runs} time(s), value #{s.verbose_with_or_equals.inspect}"

s = Settings.new
3.times { s.verbose_with_defined }
puts "defined? version, three reads: computed #{s.runs} time(s), value #{s.verbose_with_defined.inspect}"
