# `return a, b` returns one Array

**Level:** 101 · anyone who has typed `x, y = f()` in Python

**One line:** Ruby has no tuple: `return a, b` builds an Array, multiple assignment takes it apart, and a count mismatch silently pads with `nil` or drops the extras — where Python's `return a, b` builds a `tuple` and unpacking raises when the counts disagree.

A Ruby method returns one object. `return 1, 2` is `return [1, 2]`, and `x, y = pair` is multiple assignment reading from that Array — the same mechanism as `a, b = b, a`. The core library uses it everywhere: `divmod` returns a two-element Array, `partition` returns two Arrays in one, `minmax` returns a pair. A splat collects the rest (`first, *rest = …`), an underscore names a value you will not use, and `values_at` pulls several values out of a Hash in one go. When the pieces deserve names, return a `Struct` or a `Data` instead of a bare Array, and take it apart with a reader or with rightward pattern matching. The program prints each of those, then the two mismatches Ruby accepts without complaint.

## Reading the output

- **Row 1** is the claim: `return 1, 2` produced an `Array`, and there is no other type it could have been.
- **Rows 2, 6, 7** are multiple assignment: plain, with a splat collecting the tail, and with `_` as a throwaway name (it is an ordinary local that nobody reads).
- **Rows 3–5**: three core methods that return pairs, all Arrays.
- **Row 8**: `values_at` is multiple return from a Hash.
- **Rows 9–10**: named returns. A `Struct` from `divmod`'s pair has `.q` and `.r`; a `Data` is immutable and is taken apart by `c => {x:, y:}`, which binds `x` and `y` from the keys.
- **Row 11** is the difference to remember: `a, b = 1` gives `b = nil`, and `c1, c2 = [1, 2, 3]` drops the `3`. Nothing is raised.
- **Row 12**: a method with no expressions returns `nil`; there is no "no return value".

## Compared with Python

Python's `return 1, 2` builds a `tuple`, a distinct immutable type, and `x, y = pair()` is tuple unpacking. `divmod` returns a tuple, but there is no `partition` or `minmax`: row 4 writes the two comprehensions and row 5 calls `min` and `max` separately. The star and the underscore work the same way (rows 6–7), `operator.itemgetter("a", "c")` is `values_at` (row 8), and the named-return types are `collections.namedtuple` and a frozen `dataclass` (rows 9–10), with `dataclasses.astuple` for the destructuring. Row 11 is where the languages part: `a, b = 1` is a `TypeError` (an `int` cannot be unpacked) and `c1, c2 = [1, 2, 3]` is a `ValueError` (too many values). A Ruby program that miscounts continues with a `nil`; a Python one stops. Row 12: a function with no `return` gives `None`.

```ruby
# Kata: return three values two ways - as a bare Array, then as a Data.

Stats = Data.define(:min, :max, :mean)

def stats(numbers)
  return numbers.min, numbers.max, numbers.sum.fdiv(numbers.size)
end

def stats_data(numbers)
  Stats.new(*stats(numbers))
end

numbers = [4, 8, 15, 16, 23, 42]

lo, hi, mean = stats(numbers)
puts "as an Array:  #{stats(numbers).inspect}"
puts "destructured: min=#{lo} max=#{hi} mean=#{mean}"

s = stats_data(numbers)
puts "as a Data:    #{s.inspect}"
puts "by name:      s.mean=#{s.mean}"
s => { min:, max: }
puts "pattern:      min=#{min} max=#{max}"
```
